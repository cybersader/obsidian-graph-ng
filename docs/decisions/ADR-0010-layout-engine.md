# ADR-0010: Worker WebGPU layout with a Processor fallback

Date: 2026-11-17. Local implementation decision, not release or device-matrix acceptance.

**Decision.** Auto is the default. Below 5,000 projected notes it uses Processor without a GPU probe. At or above that boundary the layout worker requests a WebGPU adapter and checks the exact buffer, workgroup and binding requirements. Unsupported settings (including all-pairs repulsion or a custom tree depth) use Processor. On the first eligible run for a size bucket, both engines start from the same real input and perform up to eight steps. The Processor time includes solver construction; graphics time includes adapter/device setup, shader preparation, pipeline creation, execution and readback. Auto chooses Graphics chip only when the observed Processor time is at least 1.5 times the full graphics time. It does not amortize setup over hypothetical future steps. Trial positions are discarded. Manual Graphics skips the race, not capability checks or failure handling.

**Device scope.** The existing device preference store owns the choice and the measured samples. The cache key includes the plugin version and existing device-local room namespace. Inside it are at most 21 size-bucket rows, each containing six numbers: bucket, engine code, Processor ms, graphics ms including setup, setup ms and sampled steps. No input rows, identifiers, hardware description or timings enter shared settings. A stored result still requires a usable adapter. Denied or unavailable local storage is session-only. A one-off eight-step race is not a prediction of time to settlement for every graph in the bucket.

**Numerics.** Core remains the projection, initialization, mass, radius, adjacency and Processor authority. The GPU adapter makes transient numeric mirrors in the worker. A stable radix sort of Morton keys and a threaded binary hierarchy provide approximate repulsion; there is no second graph model and no WebGL solver. Square Morton quantization uses the Processor tree's root geometry. Each complete pair of prefix bits represents one square-cell level. A half-cell is opened, not accepted as a tight bounding box. Equal-key leaves exclude self mass. Positions and reductions are binary32, with fixed traversal and reduction order, not floating-point atomic additions. Fixed nodes still exert force. Same seed, input, options and device/engine are expected to repeat; Processor/GPU or cross-driver bit identity is not promised.

The first GPU implementation accepted tight rectangular occupied bounds. That changed the far-field force approximation as points moved. On the 2k fixture it kept moving after 20,000 steps even though the core and WGSL integration equations already agreed. The square-cell correction settles with the *same* adaptive force history, 0.3 overlap displacement damping, slowdown compensation and 0.002 relative RMS criterion. Positive thresholds remain absolute and stop after consecutive quiet steps; the default relative criterion reports settlement but does not silently change the user's iteration budget. Settlement is a motion test, not a graph-quality guarantee. See [measurements](../benchmarks.md#worker-webgpu-layout).

**Ownership and failure.** Check finite readbacks before adoption. On a failed operation, validation error, device loss, nonfinite result or five-second graphics watchdog, disable graphics in this worker session and resume Processor with the remaining steps from the last validated positions. A failed batch never becomes a warm start. Stop aborts pending graphics work. Bounded batches, explicit buffer/device destruction, late-setup cleanup and view-owned Stop on close avoid leaving a layout running across an engine switch. An application cannot preempt a browser driver or guarantee wall-clock scheduling. Large Processor layouts check an 8 ms work budget during tree construction and between 1,024-query force chunks. Discarding scratch never publishes half an integrated position column. Cold starts still require one progressed step; browser scheduling, synchronous initialization and extreme individual inputs are not a universal real-time guarantee. Measured Stop is reported separately from driver retirement.

Only authored WGSL is embedded as a compressed static asset. A missing decompressor or compiler failure is an ordinary GPU setup failure. No dynamic code evaluation, install dependency, runtime fetch, browser flag or host policy change is introduced. Packed graphs and saved layout schema are unchanged; a new producer ID prevents relabeling older solver output. Engine preference participates in cache compatibility. An exact layout-cache hit need not run either engine.
