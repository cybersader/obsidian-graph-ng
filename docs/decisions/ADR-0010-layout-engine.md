# ADR-0010: Worker WebGPU layout with a Processor fallback

Date: 2026-11-17. Local implementation decision, not release or device-matrix acceptance.

**Decision.** Auto is the default. Below 5,000 projected notes it uses Processor without a GPU probe. Larger size buckets require passing settled-quality comparisons on all three synthetic shapes: community, preferential attachment (scale-free), and grid. A quality-excluded workload stays on Processor without probing. For eligible sizes, Auto projects each engine's setup plus the requested iteration budget times its measured per-step cost. It uses the shorter relaxation budget when a movable mask is present. Up to eight trial steps use the production scheduler, convergence mode and streaming cadence, starting from identical inputs. A Graphics choice needs a projected 1.5× advantage. Trial positions are discarded. Manual Graphics skips the quality gate and race, not adapter checks or failure handling.

**Quality admission.** For each shape and size, compare three same-seed GPU/CPU pairs (17, 18, 29) against the cyclic CPU pairs (17/18, 18/29, 29/17). Use the largest absolute edge-stress difference, largest absolute sampled graph-stress difference, and largest nearest-neighbour disagreement (one minus overlap), separately. Each GPU maximum must be at most 1.25 times the corresponding CPU maximum. All six finite layouts must reach the original quiet criterion within 20,000 steps. One failed shape excludes the size class. Empty, incomplete and unmeasured classes never qualify.

**Device scope.** Only local preferences may opt into Graphics. Missing local preferences mean Auto even if imported shared settings say Graphics. Shared writes omit the engine. The device-local room namespace and plugin version isolate timing records. Format 2 stores no winner: at most 21 ten-number tuples hold size bucket, movable/threshold class, stream cadence, batch cadence, integral sample count (1..8), CPU/GPU setup ms, CPU/GPU ms per step, and measurement time. Validate types and bounds, drop samples older than seven days, and re-evaluate costs for the current budget. A remembered Processor choice needs no adapter. Only a successfully completed, non-stopped real run publishes a sample. A failed graphics operation evicts that bucket's sample; an unavailable adapter also evicts a remembered graphics choice. Storage denial leaves only in-memory state. No graph identifiers or timings enter shared settings.

**Numerics.** Core remains the projection, initialization, mass, radius, adjacency and Processor authority. The GPU adapter makes transient numeric mirrors in the worker. A stable radix sort of Morton keys and a threaded binary hierarchy provide approximate repulsion; there is no second graph model and no WebGL solver. Square Morton quantization uses the Processor tree's root geometry. Each complete pair of prefix bits represents one square-cell level. A half-cell is opened, not accepted as a tight bounding box. Key collisions are not point masses. Mixed-position cells use the normal opening test, including opening every cell containing the query. A subtree of exactly coincident positions can act as one mass for other nodes and exerts no force on itself. Positions and reductions are binary32, with fixed traversal and reduction order, not floating-point atomic additions. Fixed nodes still exert force. Same seed, input, options and device/engine are expected to repeat; Processor/GPU or cross-driver bit identity is not promised.

The first GPU implementation accepted tight rectangular occupied bounds. That changed the far-field force approximation as points moved. On the 2k fixture it kept moving after 20,000 steps even though the core and WGSL integration equations already agreed. The square-cell correction settles with the *same* adaptive force history, 0.3 overlap displacement damping, slowdown compensation and 0.002 relative RMS criterion. Positive thresholds remain absolute and stop after consecutive quiet steps; the default relative criterion reports settlement but does not silently change the user's iteration budget. Settlement is a motion test, not a graph-quality guarantee. See [measurements](../benchmarks.md#worker-webgpu-layout).

**Ownership and failure.** Check finite readbacks before adoption. On a failed operation, validation error, device loss, nonfinite result or five-second graphics watchdog, disable graphics in this worker session and resume Processor with the remaining steps from the last validated positions. The Processor restarts the quiet streak using the original criterion, not the smaller remaining budget. A failed batch never becomes a warm start. Stop aborts pending graphics work. Bounded batches, explicit buffer/device destruction, late-setup cleanup and view-owned Stop on close avoid leaving a layout running across an engine switch. An application cannot preempt a browser driver or guarantee wall-clock scheduling. Processor checks an 8 ms work budget between steps and within large walks. For Approximation below 0.5, force chunks contain 256 queries instead of 1,024. Stop before the first complete step returns the validated starting coordinates, cold or warm, without arrangement, a progress frame or settlement. Later Stop discards unfinished forces and retains the last fully integrated positions. Neither result can be encoded as settled. Browser scheduling, synchronous initialization and extreme individual inputs are not a universal real-time guarantee. Measured Stop is reported separately from driver retirement.

Only authored WGSL is embedded as a compressed static asset. A missing decompressor or compiler failure is an ordinary GPU setup failure. No dynamic code evaluation, install dependency, runtime fetch, browser flag or host policy change is introduced. Packed graphs and the saved layout schema are unchanged. Auto (no admitted size) and explicit Processor keep the pre-graphics producer, layout hash and generation key, including the seed derived from that key. An exact hit reopens without running either engine. The explicit Graphics pipeline keeps its separate producer, hash and key. A one-pass Graphics trial changes only the displayed positions. It neither adopts a worker cache generation nor replaces the ordinary disk entry. Do not restamp a Graphics request as a legacy Processor run merely because its final status names Processor: the seed was chosen before adapter discovery, and late fallback can start from validated GPU positions. A future release admitting any Auto graphics bucket must distinguish it before borrowing or saving coordinates.


## Visual stopping policy

**Finish fully** is off by default. For a relative-threshold run, both engines examine the solver's RMS displacement and RMS position extent every 16 numerical steps. The detector compensates slowdown and overlap damping like the full criterion. Four samples at or below 0.05% of extent qualify as nearly motionless. For ordinary settling it requires 72 consecutive observations within 0.4% of extent and a final narrower streak within 0.235% (two samples on Processor, eight on Graphics chip). A brief dip in GPU motion preceded stable endpoint stress in calibration. In long unpinned passes a low step speed can mask cumulative drift. Starting at step 2,048, the worker samples up to 128 evenly spaced notes every 2,048 steps (at most 1 KiB of coordinates). Once four pictures exist, the wider motion band alone no longer qualifies. Four consecutive picture intervals must have sampled RMS drift within 3% of layout extent, compensated for slowdown, and no observed step above the 1% compensated motion band. The nearly motionless path remains available. Masked incremental passes use physical settlement and the relaxation budget only. The visual stop is not calibrated for moving neighborhoods beside distant pinned notes.

On the same device, the same seed, inputs and engine repeat the same stop step. Stop steps can differ between engines. Physical settlement wins if a visual decision coincides with the step limit. Decisions do not depend on frame demand, elapsed seconds or a guessed endpoint. Graphics batch boundaries respect the sample step; partial Processor fallback starts fresh evidence. See [synthetic calibration](../benchmarks.md#visual-layout-completion).

This does not increase a step budget, infer that every note stopped moving, or change Auto graphics admission. An explicit positive absolute threshold keeps its own stopping semantics. **Finish fully** restores the prior policy: with no absolute threshold, run the requested budget and report physical settlement separately. A checked pass with no completion evidence is still unfinished. Cache and refinement semantics are in [ADR-0004](ADR-0004-worker-generations.md#visual-completion-2026-11-18).
