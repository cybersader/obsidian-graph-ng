# ADR-0009: Provisional startup from saved host facts

- Status: implemented pending independent review
- Date: 2026-11-17

## Decision

Persist only declared rows from a stable, fully verified selected-source generation. Restore them through LocalAdapter's existing column ingestion and the existing worker projection, never through a second projection implementation. A saved row is provisional input, not evidence of verification. Current host facts always win, including an explicitly unverified derived fact. No note-body reader, scanner, parser shortcut, or private host API is introduced.

Native metadata keeps its existing cache key. The optional derived source additionally needs **both** `roomFor(path)` and `rooms()`. A workspace may mount several rooms. Only the public per-path routing decision can select a partition; no vault name, URL, prefix inference or implicit `room()` is used. Hosts without either method still provide live facts but cannot save or replay derived rows.

Bind each partition to the handle’s opaque `ocpf1:` identity, using SHA-256 of the identity for its immediate directory name and including the identity in the hashed manifest key. Compare, never parse, log or display the identity. The native key is unchanged. The derived key includes a policy revision so partitions from the earlier candidate cannot supply native-fallback rows. Restore one room at a time. Remember completed restores per room, not one irrevocable promise for the entire workspace. A worker reset invalidates acknowledgements, not still-routed fallback owned by a sibling. Recheck routing before adopting and when using saved rows. Malformed partitions do not spend the shared replay budget; exceeding the aggregate budget is a miss, not grounds to delete a sibling.

Use `roomFor` only with a vault-relative path. A disposed or superseded grant can report `undefined` and an empty frozen `rooms()` array. Drop departed in-memory ownership immediately, but never treat an empty or failed inventory as disk deletion authority. Coalesce retirement into at most one pending reconciliation per adapter/cache root behind uncancellable I/O. List first, hash known identities, then re-enumerate successfully immediately before each orphan deletion. A newly seen identity vetoes the deletion. If inventory disappears, defer cleanup until a fresh nonempty inventory or the host's own purge. Native restore opens its known manifest directly and does not list partition directories.

Listen for `oc:property-facts-settled` on the same window as `oc:property-facts-changed`. Match both `cacheIdentity` and page-local `generation`, with `verifiedComplete === true` at receipt. Audit that room against acknowledged worker inputs. A verification-only change to the same value needs no replacement. A new value needs an acknowledged replacement before promotion. The event handler can await a view refresh, but only its own still-current permit can save afterward. Ordinary view refreshes never retry derived saves. No worker or no acknowledgement means no room save. A missed settlement is not inferred later.

Persist a room only when **every routed path** has a current verified derived row. Native metadata can still paint a sparse room; it cannot fill holes in a derived partition. On both sides of manifest publication, recheck the room, the complete routed path set and its acknowledged values. Withdraw a stale manifest while holding its serialization slot. Without a routing revision these two final checks require synchronous passes over the path inventory; large-host latency is unmeasured. `oc:metadata-index-settled` does not attest properties; native producer readiness still comes from public resolved links.

The host contract at `3ea6eca` returns frozen handles and its aggregate `load()` fans out. Discovery, grant changes and view opens share one window-scoped queue: re-enumerate before loading a handle, await it, then advance to the next. Do not call the multi-room aggregate loader. A legacy single-source provider can still load; a legacy room provider with no enumeration remains live-read-only. This contract is not yet deployed; synthetic fixtures are not deployed-host acceptance.

### Scheduling and retention

Host hydration uses one physical load slot per window, including across grants. A burst of opens shares a 15-second caller deadline. Expiry resolves callers and displays a quiet delayed status; it neither cancels host I/O nor releases the slot. One replaceable request waits behind that slot. On physical settlement the newest request runs, even after rejection. A failed handle does not skip healthy siblings; a failed enumeration stops that pass and reports unavailable inventory. Successful hydration clears the status. Without host cancellation, a permanently hung handle cannot make physical progress in this realm.

A room identity has one settlement drain: idle, auditing (optionally waiting for worker acknowledgement), writing, then idle. A newer valid event replaces the permit and the single pending action. Superseded callers do not join the held acknowledgement or physical write. The drain services the pending action after the active action completes. The room object, grant and permit authorize the event; worker epochs describe evidence, not authority. After acknowledgement, validate against current worker stamps before saving. A revoked grant, lost readiness, or missing acknowledgement cannot authorize publication. All physical cache I/O still uses the shared cache-root executor.

Charge replay bytes and parts only after validating the partition’s routed rows. The charge belongs to the retained rows of that generation and is released on retirement, replacement, or loss of its last fallback row. Withdraw stale publications only inside a room partition. Native publication keeps its existing post-write cancellation check without removing the native root.

## Key and invalidation

The key includes the cache/parser format, plugin version, a durable room/vault namespace, native producer/version, source/view identity, the complete declaration, and a fingerprint of the whole vault file namespace with every file's path, mtime and size, including excluded notes and non-Markdown files. The shared top-level `data.json.deviceNamespace` is a random 128-bit identifier encoded as 32 lowercase hexadecimal characters. A valid existing value is reused. A missing/invalid value is generated with `crypto.getRandomValues` and acknowledged through the ordinary serialized save path before admitting replay or saving; invalid settings refuse generation and same-instance concurrent callers await the same acknowledged write; failed saving or entropy generation disables the cache for that load. The paused storage handle remains available for explicit purge even when admission fails. Only this opaque identifier, never cached facts, enters data.json. Concurrent initial writers or resets produce a miss, not verification. These stamps are not content proof. Observed namespace, source/producer/plugin version, declaration, file-stamp or format mismatches refuse and purge the complete saved generation, not merely skip it. The purge uses the same serialized queue and deadline, without reading mismatched fact chunks. Live declaration/provider changes also schedule purge after retiring in-memory fallback, including when restore has already completed; selecting an uncached derived provider discards old native cache data. Deletion failure or timeout surfaces unavailability rather than a successful-clear claim. Same-stamp changes remain provisional until host reconciliation.

Vault edits, creates, deletes, renames, source swaps, declaration changes, disposal and clear-cache invalidate in-flight restore/save work. Host hydration does not cancel restore; available host rows supersede saved rows as they arrive through existing IncrementalIndex epochs and acknowledgements. Saving additionally requires no pending or dirty rows and a stable fact-event generation. The manifest is committed last; incomplete writes are never loaded.

## Storage and responsiveness

Use the BinaryLayoutStore pattern at `<plugin directory>/cache/startup-facts`: bounded binary chunks, shared SHA-256 checksums, a small manifest committed last, sequential I/O, cooperative yields and a 15-second end-to-end operation deadline that includes queue waiting and namespace preparation. A missing manifest avoids namespace preparation entirely. At most 100,000 whole-vault entries are admitted, collected and sorted in 256-entry runs, then cooperatively merged with yields every 1,024 entries and hashed in 256-entry slices. The exact `cache` path segment is mandatory, not configurable. The host team confirms that OpenClast's plugin-cache policy excludes path segments named `cache`, `.cache` or `caches` from replication; ordinary plugin files and data.json are room-shared. This implementation uses that reviewed host exception rather than an additional IndexedDB backend, within the approved download ceiling. It does not assert that an arbitrary host or desktop sync/backup product excludes these files.

The cache has a fixed 32 MiB generation ceiling, 1 MiB chunks, at most 100,000 rows and 4,096 chunks. Chunks flush at 256 rows, their encoded UTF-8 byte ceiling, or their 65,536-child-value budget. Save and load share the same iterative 64-level nesting and child-count validator. Save rejects cycles and nonfinite values before JSON normalization, then counts the exact serialized representation, including sparse-array nulls and each row's enclosing batch slot. A single row exceeding the byte, depth or value ceiling is refused before a successful manifest can be committed. Invalid, oversized, corrupt or version-mismatched input is refused. Unexpected downstream saved-row serialization failure discards fallback, schedules disk purge and resets the ordinary column ingestion to native rows, including when some provisional batches already reached the worker. Only one generation is retained; saving evicts the previous one first. Storage quota failures are caught, leave the host graph available, and show a short unavailable status. No storage persistence grant is requested. Browser quota remains origin-wide and shared with host caches. A timed-out uncancellable adapter operation retains its serialization slot until settlement, preventing overlapping cleanup or writes. A plugin-owned global-symbol registry uses weak public DataAdapter identity keys and a map of exact cache directories. Each storage target retains its own void-valued promise and cancellation epoch, never fact rows, across plugin module reloads in the same JavaScript realm. An old writer for that adapter and directory must settle before a new instance can finish purging or replace its generation. Different adapters or directories cannot cancel or block each other's purges. This requires the same public adapter object across plugin reloads; it does not identify equivalent wrappers or coordinate independent processes or browser realms.

The clear-saved-facts command cancels active operations, clears in-memory fallback and disk data, and pauses saving until the next plugin load, including across adapter resets. There is no durable opt-out setting in this initial command-only implementation.

## Security and privacy boundary

The cache trusts only the selected public host facts at save time. It never authenticates files, grants access, verifies a projection, overrides host disagreement or upgrades verified:false. Checksums detect damage, not malicious replacement. Restored rows still pass the ordinary declared-column validation, identity duplicate quarantine and explicit carrier-resolution pipeline. Labels stay text-only.

Disk facts include declared property values, note paths and resolved link targets. They are plaintext device-local cache data under OpenClast's exact cache-segment policy, not encrypted or scrubbed of sensitive values. They never enter room-shared data.json or ordinary replicated plugin files. Other hosts' sync and backup policies remain outside this plugin's authority. Cached facts may survive removal of the original note until replacement or clear; clearing cannot erase backups. The shared namespace identifier contains no note content. Purge on an observed local mismatch is not offline revocation or secure erasure. This implementation cannot independently authenticate room membership or erase an inaccessible directory, another realm's storage or backups; the host must own access revocation. No upload or new remote authorization boundary exists. Host facts read before progressive load completes remain provisional; once available, native metadata supersedes saved input. Nothing is written back to notes or host metadata.

## Evidence and limits

Regressions cover provisional replay, host disagreement, derived unverified facts, stale/corrupt/version-mismatched input, edits during restore and clearing. Cold-restart measurements must distinguish first saved-fact graph from verified completion and explicitly exclude the earlier same-session replay timings. Independent boundary review follows the implementation commit; deterministic gates do not substitute for that review.
