# ADR-0008: adaptive presentation and local performance observations

Date: 2026-11-17. Status: local candidate; size admission and independent review remain separate.

## Decision

Make device cost visible without changing graph meaning or the settled solver. The browser-native synthetic baseline separates host metadata hydration, plugin ingestion, worker layout and detail initialization. CPU throttling is not a GPU or RAM emulator. A browser tab's reported resident memory cannot be attributed from main-realm JavaScript heap alone. The measurements and exact limitations belong in [benchmarks](../benchmarks.md#adaptive-performance-and-anchored-label-memory).

1. **Detection:** CPU concurrency and optional device memory provide a provisional low/standard tier. The existing WebGL context supplies texture capability and a coarse software-renderer check; detection never creates another context. A bounded ten-second long-task observer and constant-space measured draw-cost average can demote the guess. Sustained inexpensive drawing can promote it again, with hysteresis. Missing signals mean a provisional standard tier, not a claim of strong hardware. These are policy thresholds, not browser-vendor performance ratings.
2. **Progressive loading:** retain the reviewed worker streaming, deferred captions/picking, usable camera and Stop transaction. Fast/low Auto permits the first progressed five-iteration batch rather than waiting for two batches. No seed-only frame is admitted. Final iterations, convergence, layout identity, worker deadlines, cache validity and Quality coordinates are unchanged. Initial Groups already paints before the full layout. No second solver or projection authority is added.
3. **Adaptive quality:** Fast and low Auto cap drawing resolution at one device pixel per CSS pixel and apply instant rather than animated camera/focus states. Quality respects original DPR and motion settings. Drawing already sleeps entirely while idle; no periodic idle frame loop is added. Label and edge budgets remain explicit existing settings, not silently truncated semantics. The default Anchored label style now retains identical ranked candidate/placement metadata without allocating an unused 2048-square RGBA canvas, glyph geometry or full-size GPU texture. Ranked labels retain their raster and exact geometry. Texture storage is reused when dimensions match and reallocated across style changes.
4. **Owner control:** Auto is the default, alongside Fast and Quality. A dotted-help tier term explains the estimate. A performance suggestions modal is offered automatically at most once, with the offered flag persisted across reloads on low-tier, large-graph or high measured main-heap evidence. It suggests Fast mode first when the effective mode is not already Fast, followed by currently enabled work: ranked labels, visible curved edges, full motion and relationship-note dots. Fast mode joins the same save-before-adopt transaction; opting out preserves the current mode. When no changes remain, neither an empty disclosure nor a no-op primary is shown. The title and one dotted-help reason line come from the same admission decision, with named note/edge counts or measured timing/memory. Device hints remain provisional; long tasks and main-realm memory describe the app, not proven graph ownership. No layout-duration cause is invented. All changes start selected behind a collapsed Choose changes caret; Speed up applies the selected changes in one click. No toggle takes effect before the acknowledged save. Not now and the native X dismiss it without another automatic offer. Manual opens also claim the offered flag; an open/applying guard prevents re-entry during rebuilds. Don't ask again disables automatic offers persistently. Speed up graph reopens it from Performance even after suppression. Relationship Lines changes are explicit user choices, never automatic optimization.
5. **Local diagnostics:** default off. Opt-in permits at most 16 numeric samples in `data.json.performanceLog`, recording counts, stage durations, measured draw/long-task summaries, optional main JS heap bytes, coarse tier and mode. A fixed allowlist sanitizes both load and save; strings in numeric fields, nonfinite/negative numbers and unknown keys are dropped. No note names, paths, queries, content, renderer strings, device identifiers or stack/error text are stored. Disabling or Clear removes retained samples on the next acknowledged settings save. No request, export or remote telemetry is introduced. Anyone who can read plugin data can read these observations; this is not a new authorization boundary.

## Scope and remaining work

The storage decision supersedes only ADR-0004's statement that data.json contains settings alone. Settings migration/quarantine and all existing source and cache boundaries remain intact. Optional instrumentation and suggestions cannot fail an otherwise valid graph operation. The modal uses the existing acknowledged candidate-write queue and adopts only after save, preserving live settings on rejected writes. Controls resolve current settings at event time and only the settings tab’s Performance controls redraw after successful Speed up, preserving JSON drafts; unrelated controls and the bottom-left progress control are not redesigned.

A 5k synthetic main/worker snapshot is recorded in the benchmark document; the 49k full snapshot exceeded its bounded session and remains an explicit attribution gap. Main/worker projection duplication is deliberate: main retains packed render-only columns while the worker retains identity, facts and the solver. Recycled streaming buffers are already bounded to two. This slice does not discard source facts, weaken duplicate quarantine, remove rollback coordinates or reinterpret saved layouts merely to lower memory. Worker heap, GPU driver allocations, browser-native/DOM memory, retained host caches, high-DPR hardware and actual low-memory laptops require separate attribution. The reported 2.5 GB tab is not reproduced or explained by a small synthetic JS-heap sample. Further allocation changes need measured ownership and their own regressions.

Long-task totals describe contention in the shared main realm, not proof that Graph NG caused each task. The browser CPU-throttle setting may not slow the dedicated layout worker identically. Shared-host timing and SwiftShader frames are indicative, not hardware acceptance. A single run per lane cannot establish a statistical speedup. Build/test success and local screenshots do not grant a size-cap change, release, publication or deployment.
