# ADR-0006: CSR-native ForceAtlas2 with a development-only oracle

Date: 2026-11-10. Status: implemented locally; exact commands, measurements and gaps are in [benchmarks](../benchmarks.md#slice-4-csr-native-layout). Supersedes the interim worker-layout choice in ADR-0002/0004/0005. This is not publication or compatibility-matrix acceptance.

## Decision

The existing long-lived worker runs an original deterministic ForceAtlas2 integrator directly over projection typed arrays. CSR offsets supply degree-plus-one mass; source/target columns retain directed attraction and parallel edges. Older edge-only harness callers compute degree into the same mass column. The solver has no per-node or per-edge JavaScript object graph. Positions, force/history, convergence and mass are typed arrays. A reusable flat quadtree stores geometry, mass moments, children, leaf ownership and threaded traversal links in typed arrays; cells are not objects either.

Graphology 0.26.0 and graphology-layout-forceatlas2 0.10.1 remain exactly pinned **development dependencies only**, for differential tests and the offline benchmark. No runtime source imports them. Both embedded worker and main bundle builds assert that their complete input graphs contain no `node_modules` files. The runtime-license gate enforces an empty dependency set and regenerates an empty `THIRD_PARTY_NOTICES.txt`. The bundle gate now enforces 150,000 minified bytes and 45,000 gzip bytes, not the looser intermediate ceilings.

The force equations follow Jacomy et al., *ForceAtlas2, a Continuous Graph Layout Algorithm for Handy Network Visualization Designed for the Gephi Software*, PLOS ONE (2014), doi:10.1371/journal.pone.0098679. The oracle is a comparison implementation, not bundled implementation code. Supported existing knobs retain linear/LinLog attraction, degree-distributed attraction, normal/strong gravity, scaling, slowdown, Barnes–Hut and size adjustment. Projection edges have unit weight, so `edgeWeightInfluence` has no effect until weighted input exists. Like the oracle, Barnes–Hut uses point masses even with `adjustSizes`; direct all-pairs mode applies radius-aware pair forces. Size adjustment limits movement forces using configurable `maxForce`/`nodeRadius`.

## Numerical and scheduling contracts

- Seeded LCG initial positions and fixed input/iteration order make the same inputs/options deterministic within the same JavaScript runtime. Cross-engine bitwise equality is not promised.
- The integrator retains force/convergence history across worker yields and emitted snapshots. `batchIterations` (default 5) bounds iterations per worker task; `streamEveryIterations` independently controls snapshot cadence. Buffer recycling never aliases authoritative solver positions. Changing scheduling cadence does not change the final hash.
- `iterations`/`relaxIterations` bound total work. `convergenceThreshold` is RMS movement in layout units; zero disables early exit by default. `convergenceIterations` consecutive quiet iterations (default 3) are required. There is no nondeterministic wall-clock numerical cutoff. One iteration may still take substantial time on very large inputs; the existing terminable-worker processing deadline remains the backstop, not an interactive latency guarantee.
- The standard Barnes–Hut opening rule is cell width / center-of-mass distance < `barnesHutTheta` (default 1.2), with containing cells always opened. The development oracle uses twice the cell width for the same nominal theta; equal theta is not equal approximation effort. Depth-limited mass buckets exclude the member's own mass and prevent coincident points from unbounded subdivision or quadratic leaf scans. `maxTreeDepth` defaults to 32 and is bounded by floating-point precision. Coincident points are not randomly jittered.
- Warm starts copy saved positions without mutating them. The existing `movable` mask identifies changed/new endpoints and one-hop neighbors. All other coordinates remain **bitwise unchanged**; pinned nodes still exert forces. Pure attribute changes do not globally relayout.

## Cache and versioning

The producer changes to `graph-ng-fa2@1`, invalidating exact keys from the old batch-reset solver. Existing source/declaration/layout/producer compatibility checks reject old binary generations rather than stamping their coordinates as current output. `CACHE_FORMAT` remains **3**: the encoding is still identical Float32 position columns and existing identity/topology/group sections. Solver semantics are a producer change, not a binary-format change. Package, manifest and versions map advance together to **0.2.0**. Settings upgrades fill the new knobs while preserving previous force/iteration choices. The legacy JSON migration still recognizes the old graphology producer string, but its exact layout hash lacks the new solver knobs and therefore cannot match the current config: that branch is unreachable for genuine old generations. It remains inert compatibility scaffolding, not a claim that old graphology coordinates migrate into the new producer; such generations rebuild. Removal of the obsolete protocol branch is deferred rather than changing runtime behavior in this test-hardening follow-up.

## Acceptance and limits

The oracle comparison uses fixed graph/seed/initial positions and 50 continuous iterations. Measure optimal-uniform-scale unit-edge stress `1 - sum(length)^2 / (edgeCount * sum(length^2))` and RMS-normalized edge-length q10/q50/q90. Tests require absolute stress delta <0.08, maximum relative quantile deviation <25% and an unnormalized median-edge scale ratio within 15%; these tolerate rotations and alternative local minima instead of pretending coordinates must be identical. Separate 20-iteration all-pairs comparisons check equations and integration history against the oracle at <1e-6 maximum coordinate error across supported force modes. Tiny-theta tree forces are compared to brute force, and theta 0.7 has a <5% relative L2 force-error bound across three fixed seeds; these detect approximation/force-scale regressions hidden by normalized distributions. Distribution similarity is not proof of global neighborhood preservation or human readability.

Multilevel coarsening for **>250,000 nodes is deferred**. No million-node timing/memory acceptance, mobile/iGPU proof or native FPS claim is added. The measured 16,000/60,600-node fixtures do not establish that range. The existing group-first renderer, projection rebuilding and cache storage contracts remain unchanged.


## Optional family attraction (wave 11)

Family pull adds a linear spring on each resolved child-parent CSR entry, independent of drawn edges. Its coefficient is `familyPull / sqrt(familyDegree[child] * familyDegree[parent])`; family degree counts incoming and outgoing declared parent entries, not link degree. Equal and opposite contributions preserve symmetry. Self/unresolved/duplicate references are already removed by projection; cycles and multiple parents require no traversal. Shared parents indirectly gather siblings, so no separate sibling setting was added.

The optional degree column costs 4 bytes per note, is allocated only with active family pull, and does not change repulsion mass. Each step adds O(notes + parent entries) work, never O(siblings squared), to existing link attraction/Barnes-Hut work. Family attraction is linear even in LinLog mode, respects size-adjusted contact, and shares the existing slowdown, convergence history, pinned-node behavior and worker deadlines. With pull 0, arithmetic and historical cache identity remain unchanged. The main slider is hidden without a declared hierarchy; all presets leave the feature off. Parent-data cache handling is specified in ADR-0004; measurements and acknowledged limits are in the benchmark document.


## Large-graph initialization and refinement (wave 12)

The current producer is `graph-ng-fa2@2`; the historical producer/migration description above is superseded by ADR-0004's settled-generation amendment. Cold LCG seeds are uniform in a disc whose radius is `initialRadius * sqrt(noteCount)`. No ontology or group labels influence initialization. Snapshot/final placement puts genuinely unlinked notes into ordered outer rings without modifying connected coordinates or pinned isolates. Pinned isolate radii bound new rings, avoiding occupied old positions. Hierarchy participants remain solver-driven.

Hub gravity is finite 0..10, default 2, with Family pull still 0. Each existing edge contributes additional linear attraction only to its smaller-degree endpoint. Its coefficient is `hubGravity * sqrt(mass[larger]) / sum(sqrt(mass[largerNeighbours]))`, where mass is the existing degree-plus-one column. Equal-degree edges contribute no extra force, and the larger endpoint receives no extra recoil. Parallel edges cannot increase the total normalized coefficient per follower. Work is O(edges) per step plus one 4-byte-per-note normalization column when enabled; Barnes-Hut repulsion is unchanged. Filters do not delete topology, so hidden hubs retain their force influence.

Zero convergence threshold still disables early termination, but settlement uses slowdown-compensated RMS step <= 0.002 times RMS distance from the origin. An explicit positive threshold retains absolute-unit semantics. Quiet iterations required are capped at the active iteration budget, so a stationary one-step refinement can settle. Budget exhaustion alone never implies settlement. Recommended grows to 300..1000 iterations; the existing 120-second default worker deadline bounds runtime by termination rather than changing numerical output nondeterministically. The criterion is a practical movement test, not a clustering-quality certificate. Synthetic 16k and 32k runs can still be unsettled and require another explicit refinement.


## Size-aware repulsion correction (2026-11-16)

The previous Barnes-Hut path never read node size. Turning on `adjustSizes` instead clipped each total force to `maxForce` (10) and fixed the integration coefficient at 0.1. On large cold seeds this retained nearly the initial disc while its tiny relative movement incorrectly satisfied settlement. The size-dependent `continue` in edge attraction was correct contact handling, not a skipped region repulsion.

Active overlap mode allocates one Float32 radius per note: `nodeRadius * max(1, sqrt(noteCount) / 16) * sqrt(1 + 24 * sqrt(degree / maxDegree))`. The degree curve matches the default renderer's sqrt-degree **area** curve with 5x maximum hub radius. The count factor supplies layout-unit spacing at larger graph extents; it is a calibrated camera-independent proxy, not a CSS-pixel conversion. It deliberately does not import renderer/settings code into the core or make viewport, appearance, carrier style or zoom part of physics. Unlinked-note rings remain presentation-only.

Exact pairs and the tree use surface distance softened to at least half the center distance. Repulsion increases by at most 4x, avoiding singular contact impulses. Singleton leaves use their own radii; aggregate cells conservatively use the global maximum radius. The opening test uses softened distance, so a near region is opened rather than dropped. Its work is bounded by the existing theta/2 opening test: same reusable tree, depth-limited mass buckets and Barnes-Hut complexity, no pairwise pass added. Exact coincidence still has no direction; this is not a hard-disc packing solver. Warm-start masks and fixed-coordinate guarantees remain unchanged.

The force cap is removed (`maxForce` stays accepted as a legacy settings/identity field). The existing adaptive integrator applies a 0.3 displacement coefficient in overlap mode, after updating convergence. The coefficient must not feed back into the convergence recurrence, which would compound damping and invalidate settlement compensation. A zero convergence value restarts only in overlap mode so a temporarily balanced node can respond after its neighbours move. Ordinary mode is numerically unchanged. Relative settlement compensates for the single displacement coefficient as well as user slowdown. Explicit positive convergence thresholds retain absolute-movement semantics. Neither measured 5k nor 20k cold Recommended run settled in 300 steps, and neither is now reported as settled. Refinement remains explicit.

This intentionally diverges from the pinned graphology size-adjusted integrator and its radius-ignorant Barnes-Hut branch. Exact 20-step oracle equality still covers all ordinary force modes with overlap off; stress/quantile oracle tests remain. Overlap mode instead has softened-force differential tests, pinned/streamed-determinism checks, and a fixed-seed 5k drawn-disc regression at home and 5x close zoom. Measurements use renderer size helpers, not proxy radii. Extreme 25x appearance can still increase home-fit overlap, so help and acceptance do not claim unconditional screen-space non-overlap.

## Morton query locality (2026-11-17)

Barnes-Hut layouts with at least 20,000 nodes visit query nodes in Morton (Z-order) rather than input order. The first tree build and every eighth build thereafter refresh the permutation from current positions and the existing bounds scan. Refresh uses 16-bit coordinates per axis and a stable, unsigned four-pass byte-radix sort. Three count-sized Uint32 columns and 256 histogram counters are allocated once with the tree: **12 bytes per node plus 1,024 bytes**, no refresh/step scratch allocations. Smaller layouts and the all-pairs path allocate none of this state. The existing tree-capacity growth policy is unchanged.

Only the outer query visitation order changes. Tree insertion, cell mass accumulation, threaded traversal within each query, each node's force arithmetic, attraction, integration and movement reductions retain their original order. Each query writes only its own force slots. This preserves bit-identical Float32 coordinates, including radius-aware repulsion, pinned warm starts and depth-limited buckets; it is not an approximation or reduced iteration budget. An older permutation can reduce locality but cannot change the force result. Cache identity, producer, settings, projection authority and binary format therefore stay unchanged.

The 50 ms cooperative work check and message-friendly worker yield are unchanged. One solver step remains atomic, and a terminable-worker deadline remains the backstop. Gated parity, unsigned/stable ordering, eight-build cadence, scratch identity and actual-worker initial/refinement Stop regressions accompany the change. Paired headless Chromium worker measurements and their limits are recorded in the benchmark document. The 20k gate is conservative: the measured 5k lane keeps ordering disabled and does not establish a lower crossover. No mobile, hardware-GPU or whole-app startup acceptance follows from solver timing.
