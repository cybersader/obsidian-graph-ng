# ADR-0006: CSR-native ForceAtlas2 with a development-only oracle

Date: 2026-11-10. Status: implemented locally; exact commands, measurements and gaps are in [benchmarks](../benchmarks.md#slice-4-csr-native-layout). Supersedes the interim worker-layout choice in ADR-0002/0004/0005. This is not publication or compatibility-matrix acceptance.

## Decision

The existing long-lived worker runs an original deterministic ForceAtlas2 integrator directly over projection typed arrays. CSR offsets supply degree-plus-one mass; source/target columns retain directed attraction and parallel edges. Older edge-only harness callers compute degree into the same mass column. The solver has no per-node or per-edge JavaScript object graph. Positions, force/history, convergence and mass are typed arrays. A reusable flat quadtree stores geometry, mass moments, children, leaf ownership and threaded traversal links in typed arrays; cells are not objects either.

Graphology 0.26.0 and graphology-layout-forceatlas2 0.10.1 remain exactly pinned **development dependencies only**, for differential tests and the offline benchmark. No runtime source imports them. Both embedded worker and main bundle builds assert that their complete input graphs contain no `node_modules` files. The runtime-license gate enforces an empty dependency set and regenerates an empty `THIRD_PARTY_NOTICES.txt`. The bundle gate now enforces 150,000 minified bytes and 45,000 gzip bytes, not the looser intermediate ceilings.

The force equations follow Jacomy et al., *ForceAtlas2, a Continuous Graph Layout Algorithm for Handy Network Visualization Designed for the Gephi Software*, PLOS ONE (2014), doi:10.1371/journal.pone.0098679. The oracle is a comparison implementation, not bundled implementation code. Supported existing knobs retain linear/LinLog attraction, degree-distributed attraction, normal/strong gravity, scaling, slowdown, Barnes–Hut and size adjustment. Projection edges have unit weight, so `edgeWeightInfluence` has no effect until weighted input exists. Like the oracle, Barnes–Hut uses point masses even with `adjustSizes`; direct all-pairs mode applies radius-aware pair forces. Size adjustment limits movement forces using configurable `maxForce`/`nodeRadius`.

## Numerical and scheduling contracts

- Seeded LCG initial positions and fixed input/iteration order make the same inputs/options deterministic within the same JavaScript runtime. Cross-engine bitwise equality is not promised.
- The integrator retains force/convergence history across worker yields and emitted snapshots. `batchIterations` (default 5) bounds iterations per worker task; `streamEveryIterations` independently controls snapshot cadence. Buffer recycling never aliases authoritative solver positions. Changing scheduling cadence does not change the final hash.
- `iterations`/`relaxIterations` bound total work. `convergenceThreshold` is RMS movement in layout units; zero disables early exit by default. `convergenceIterations` consecutive quiet iterations (default 3) are required. There is no nondeterministic wall-clock numerical cutoff. One iteration may still take substantial time on very large inputs; the existing terminable-worker processing deadline remains the backstop, not an interactive latency guarantee.
- The standard Barnes–Hut opening rule is cell width / center-of-mass distance < `barnesHutTheta` (default 1.2), with containing cells always opened. The development oracle uses twice the cell width for the same nominal theta; equal theta is not equal approximation effort. Depth-limited mass buckets exclude the member's own mass and prevent coincident points from unbounded subdivision or quadratic leaf scans. `maxTreeDepth` defaults to 32 and is bounded by floating-point precision. Coincident points are not randomly jittered.
- Warm starts copy saved positions without mutating them. The existing `movable` mask identifies changed/new endpoints and one-hop neighbors. All other coordinates remain **bitwise unchanged**; pinned nodes still exert forces. Pure attribute changes do not globally relayout.

## Cache and versioning

The producer changes to `graph-ng-fa2@1`, invalidating exact keys from the old batch-reset solver. Existing source/declaration/layout/producer compatibility checks reject old binary generations rather than stamping their coordinates as current output. `CACHE_FORMAT` remains **3**: the encoding is still identical Float32 position columns and existing identity/topology/group sections. Solver semantics are a producer change, not a binary-format change. Package, manifest and versions map advance together to **0.2.0**. Settings upgrades fill the new knobs while preserving previous force/iteration choices. The legacy JSON migration still recognizes the old graphology producer string, but its exact layout hash lacks the new solver knobs and therefore cannot match the current config: that branch is unreachable for genuine old generations. It remains inert compatibility scaffolding, not a claim that old graphology coordinates migrate into the new producer; such generations rebuild. Removal of the obsolete protocol branch is deferred rather than changing runtime behavior in this test-hardening follow-up.

## Acceptance and limits

The oracle comparison uses fixed graph/seed/initial positions and 50 continuous iterations. Measure optimal-uniform-scale unit-edge stress `1 - sum(length)^2 / (edgeCount * sum(length^2))` and RMS-normalized edge-length q10/q50/q90. Tests require absolute stress delta <0.08, maximum relative quantile deviation <25% and an unnormalized median-edge scale ratio within 15%; these tolerate rotations and alternative local minima instead of pretending coordinates must be identical. Separate 20-iteration all-pairs comparisons check equations and integration history against the oracle at <1e-6 maximum coordinate error across supported force modes. Tiny-theta tree forces are compared to brute force, and theta 0.7 has a <5% relative L2 force-error bound across three fixed seeds; these detect approximation/force-scale regressions hidden by normalized distributions. Distribution similarity is not proof of global neighborhood preservation or human readability.

Multilevel coarsening for **>250,000 nodes is deferred**. No million-node timing/memory acceptance, mobile/iGPU proof or native FPS claim is added. The measured 16,000/60,600-node fixtures do not establish that range. The existing group-first renderer, projection rebuilding and cache storage contracts remain unchanged.
