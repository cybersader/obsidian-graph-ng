# ADR-0007: profile native startup and transfer render-only columns

Date: 2026-11-10. Status: implemented locally; independent release review remains separate.

## Evidence and decision

Real Obsidian 1.13.7 CPU sampling and public long-task entries attribute the cold explicit-detail blocker to Graph NG's GPU capability probe: `gpuStatus` creates the first WebGL context on the main thread. This is plugin-requested driver initialization, not a task attributable to Obsidian's UI. Serial row-column packing and worker dictionary decoding account for substantial time before group delivery; a seven-control group list is not the large-vault bottleneck. Raw profiles, exact commands and before/after results are in the private benchmark evidence described by [the benchmark record](../benchmarks.md#slice-5-native-startup-and-retained-render-columns).

Use a public worker `OffscreenCanvas` for the capability probe, only after explicit detail/member interaction. Keep the existing main-canvas public-API fallback when the worker platform has no OffscreenCanvas. Shader construction, deadlines, software refusal budgets and context-restoration behavior remain unchanged. Revision checks after the new await prevent stale navigation from creating a renderer. Probe failures retain groups/member lists and surface a notice.

Keep the full ontology-neutral projection exclusively in its existing worker. Transfer only the numeric drawing/picking columns, edge-type dictionary, group-value dictionaries and quarantined-note notices needed by the main UI. Encode node paths as a contiguous UTF-8 dictionary with offsets; decode only bounded label candidates, visible member rows and hovered/clicked items. Do not retain a second main-thread identity, property, carrier or membership-code authority. Existing paged worker member/contribution APIs remain the source for those operations.

Optimize contiguous ASCII dictionary encoding/decoding without changing the format. Unicode cells retain independent encoding/decoding, including isolated surrogate replacement and invalid UTF-8/cell-boundary rejection. Property-only declarations skip extraction of unused producer-link targets. Native full-path tracing also identified palette `getImageData` GPU synchronization on Groups redraw and the external carrier lookup scanning metadata without a yield. Palette conversion now requests a one-pixel CPU-backed (`willReadFrequently`) surface. Carrier indexing shares the synchronous resolver accumulator but yields under existing ingestion budgets; superseded panels discard unfinished lookups. A drill-to-note profile attributed a further 94 ms task (91.1 ms sampled) to resizing a GPU drawing buffer while parallel shader compilation was pending. Keep CSS geometry responsive, but defer GPU buffer dimensions until program completion; never assign an unchanged dimension, because even an equal assignment resets the buffer. Latest pending dimensions are applied before upload and reconciled again immediately before readiness, including the shared context-restoration path. Refresh increments the interaction revision at lookup invalidation so a pending scan cannot repopulate a stale cache while a replacement graph is still loading. No ontology key, path prefix or fixture identity receives a special case. Existing ingestion row/time budgets, label/list/canvas budgets and worker deadlines remain configurable; no new input cardinality limit is introduced.

## Measurement correction

A metadata-triggered refresh can repaint groups before the harness reads the DOM. The prior `firstGroupMs` field was overwritten by that later refresh. Preserve the first actual live group paint for a view lifetime, expose the latest refresh separately, and keep a bounded 16-entry phase trace. Report both actual cold paint and later verification refreshes rather than presenting one as the other. GPU probe time on a worker is not main-thread blocking time; shader polling elapsed time is not a long-task duration.

## Consequences and limits

Packed paths exchange JavaScript heap objects for explicitly measured ArrayBuffer backing storage. The browser benchmark keeps the same host metadata alive before/after and reports both measures; a JavaScript heap goal is not a total process-memory goal. Worker memory, GPU/native memory, integrated/mobile GPU behavior and native FPS remain unaccepted. OffscreenCanvas-unavailable platforms may retain the original blocking main-thread probe. A single oversized property, host API call or driver operation is not made preemptible by batch budgets. No Obsidian internals, runtime dependency, persisted cache format, projection authority or authorization behavior changes.

The final GPU-resize approach flushes a public WebGL2 fence and asynchronously polls clientWaitSync with flags/timeouts both zero, under existing shaderPollMs/workerTimeoutMs budgets. Both pre-upload and final pre-ready reconciliations wait for GPU completion. Every created fence is deleted on completion, failure, lost/disposed cancellation or timeout; initialization failure retains the existing group fallback. This removed a reproduced 230 ms drawing-buffer task in the targeted actual-native rerun (309.1 ms first groups; heap about 10.9 MiB). Driver allocation remains non-preemptible.

## Local results

Native large first groups are 320.0/350.1 ms hardware/software, down from 535.3/589.5 ms in the same baseline profile. Browser main JS heap is 10.97/10.94 MiB semantic/literal, excluding separately reported backing storage. Recorded 62–70 ms detail tasks remain a miss, with ownership left unattributed unless the exact retained CPU profile supports it; software-open 51–63 ms events exceed the 50 ms target, have only program/incomplete samples and remain UNATTRIBUTED. Independent SHIP-WITH-FIXES review led to upload-window and stale-lookup regressions; see the benchmark record for final commands, run paths and remaining lanes.
