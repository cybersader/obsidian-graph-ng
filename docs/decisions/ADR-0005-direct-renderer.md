# ADR-0005: direct typed-array renderer and persistent relationship intent

Date: 2026-11-10. Status: implemented locally; exact verification and remaining targets are in [benchmarks](../benchmarks.md#slice-3-direct-renderer). Supersedes the interim detail renderer in ADR-0002 and the Sigma-specific renderer limitation in ADR-0004. It does not replace the worker layout or establish remote acceptance.

## Decision

The detail renderer consumes the engine-neutral projection and Float32 positions directly. WebGL2 draws instanced circular node quads and straight edge quads, with RG32F positions and an indexed RGBA8 color palette. Camera updates change uniforms, not graph buffers or a second object graph. Sigma and main-thread Graphology construction are removed. Graphology/FA2 remain exclusively in the existing worker layout; extracting its options prevents settings from retaining layout code in the main runtime graph. Both bundles are minified, including the worker before it is embedded as a string.

Node picking uses a packed CPU uniform grid with deterministic nearest-hit ties; nearby edge hover visits incident-edge CSR. Picking does not read pixels back from the GPU. Click navigation retains exact local-file resolution. Ranked labels are Canvas-rasterized glyphs, never interpreted markup or shader source. Degree-prioritized candidates and viewport-derived budgets feed collision-checked placements at seven conservative zoom LODs. Atlas dimensions, candidate count, string length and label count are bounded. Fonts or viewport size can rebuild placement; camera drawing does no per-frame label measurement or graph reconstruction. Label choices are global LOD subsets, not viewport-local re-ranking on every pan.

CSS variables `--graph-ng-bg|node|edge|group|text|accent|font` fall back to the host graph/background/font variables and validated defaults. Declared colors accept hex RGB/RGBA or a restricted CSS variable reference. `css-change` and color-scheme changes reread computed colors and upload the palette without worker calls, layout or graph-buffer replacement. A font change separately rebuilds glyphs. The initial 256-entry palette expands by rows for larger declarations.

Program linking uses nonblocking `KHR_parallel_shader_compile` completion queries when available, with timer yields and a deadline. Without the extension, driver link-status checks may still block; a hardware result cannot prove every driver. Painting is on demand through rAF plus one configurable `frameBackstopMs` timer (32 ms default) for embedded windows that withhold rAF. `shaderPollMs` defaults to 8 ms; camera bounds and label-candidate multiplier are settings too. It is not a continuous background animation loop. Context loss retains CPU arrays and disables drawing/hit interaction; restoration recompiles/reuploads. If restoration does not complete within `contextRestoreTimeoutMs` (5 seconds by default), or fails, the view switches to bounded Canvas detail or groups. Disposal removes listeners, cancels timers, explicitly loses its WebGL context and prevents failed restoration from reopening a disposed view.

Paged Canvas2D groups remain the primary overview. Software-only detail is allowed within both validated `canvasMaxDetailNodes` / `canvasMaxDetailEdges` budgets, default 2,000 visible nodes / 10,000 visible edges. Eligible edge indices are prepared once; frame drawing does not scan every hidden edge or truncate excess relationships. Larger views retain groups and member lists with a visible fallback notice. The plan's proposed 20,000-node default is deferred: the native software proof reaches 600/1,400, not 20,000 nodes, and even the conservative refusal boundary is not a measured FPS guarantee.

## Traversed isolation and explicit visual intent (2026-11-16)

Only connections now retains a bounded set of traversed edge indices alongside its node mask, not the full induced subgraph among retained nodes. This removes unrelated neighbour-hub fans. Explicit typed carrier ownership already provides semantic one-hop traversal through relationship notes; no parser, ontology shortcut or second projection authority is added. Type filters, traversal budgets, additive expansion and host-filtered navigator contents remain independent. Entry frames the retained region; exit does not refit or change zoom, although normal card-safe panning can still apply.

The selected node has a final single-instance WebGL pass after isolated edges (with the selected size attribute explicitly supplied and restored), and an equivalent final Canvas pass. It stays filled, ringed and at least five CSS px in radius even when highlighting is disabled or ordinary relationship dots fold away. Adaptive dense direct dots retain a larger fraction of the minimum radius. Frontier badges show at most six ranked hidden-neighbour counts with an aggregate for the rest.

The Click a note selector interprets the existing clickOpens/hoverHighlight pair without migration changes. Hub size retains degreeSizing as prominence minus one, now allowing 1x through 25x; the historical radius ceiling is preserved, with a combined radius-times-prominence precision bound. Name priority adds connected (default), selection and all choices while reusing bounded atlas and focus candidates. All that fit is not an unbounded promise to label every note. Renderer/native acceptance limits remain as recorded in benchmarks.

## Card-safe selection and reversible isolation (2026-11-16)

Card geometry is measured before framing and reuses the existing right/bottom unobscured-stage insets. `visuals.cardPlacement` is `auto` by default, with `side` and `sheet` alternatives. Auto uses a sheet below 720 px of available width; an open tools panel forces a sheet whenever a side card would leave less than 420 px or 45% of the stage. Only note sheets beside tools fold initially; their header and Open note remain available, with a caret exposing the existing single scroll region. Edge/path cards are not folded.

`visuals.clickFraming` defaults to `off`: a covered selection gets only an instant minimal safety pan, without zoom. `center` moves a selection outside the comfortable area to the unobscured centre; `fit-neighbours` uses the existing bounded one-hop traversal and fit helper only when needed. Travel shares measured geometry and rendered coordinates. Existing Motion and OS preference handling governs camera flights; no idle work or new projection authority is introduced. Isolation toggles from the entry button and chip X share the existing mask and do not automatically fit. The chip's brief border notice is disabled under reduced/off motion.

Relationship row captions follow explicit carrier ownership and directed legs, never filename syntax. Unresolved endpoints retain the ordinary note fallback. This is presentation only; filtering, IDs and graph authority are unchanged. Referenced text names avoid Obsidian's row aria-label tooltip, and keyboard focus expands a truncated name. Regression tests and synthetic browser-native software-WebGL captures cover placement, isolation, names and framing. Independent merged review, hardware-driver and screen-reader acceptance remain separate.

## Bounded motion and preview handoff (2026-11-16)

`visuals.motion` is `full` (default, including upgrades), `reduced` or `off`. Full preserves the single-note hover: 150 ms ease-out to 1.6x, two one-second ring breaths with amplitude .04, then a static ring. Leaving returns over 120 ms. The previous indefinite breathing loop is removed. Reduced, Off and the OS reduced-motion preference all apply instant states for camera, focus, hover and lens and suppress the selection ripple. Reduced and Off deliberately have identical renderer behavior in this slice. A live media-query listener settles an active transition on its next requested frame and is removed on disposal.

Focus fades now use the camera's cubic in-out curve over 220 ms; camera duration remains configurable (450 ms default). Selection ripple remains bounded to 250 ms. Hover is not a second focus: only the hovered note changes size and ring. New animation work consists of scalar state/uniform changes, shared by WebGL and the existing bounded Canvas path; no new position/state textures, node traversal or graph authority are added. Existing bounded label/pip work still runs on drawn frames. There are no scheduled animation frames after settling, including while a pointer remains over a note.

For the loading handoff, `LayoutPreview.finish(true)` closes stream admission and waits out obsolete initialization without disposing a completed preview. Final construction hides its new canvas until a synchronous first draw completes. The old preview stays in the shared stage until that point, then is disposed; the existing `finally` releases its coordinates. This fixes the deliberate empty-stage interval, not layout continuity: final positions and camera can still change abruptly, and an initializing preview can still delay the handoff. Position interpolation, distance-staggered neighbour reveal and filter/group cross-fades remain deferred. Independent merged-wave review and hardware-driver acceptance remain separate from the scoped tests and Canvas harness measurements in the benchmark record.

## Anchored names (2026-11-16)

`visuals.labelStyle` defaults to `anchored`, including upgrades missing the key; `ranked` retains the earlier atlas geometry, type scale, importance cut, fades and focus layout. Degree chooses overview candidates but no longer changes the anchored text size. Anchored names use `labelSize`, full opacity, and an explicit ring plus an eight-pixel leader on each named dot. This separates label readability from node radius. Canvas keyboard help moves from the host-tooltipped `aria-label` to a hidden `aria-describedby`; native path/title tooltips are removed for both styles.

Both renderers call the same anchored overlay. Overview reuses the ranked atlas's existing grid-selected placements for the current sticky zoom level, already bounded by `labelsMaxPerViewport`, the grid density and `labelCandidateMultiplier`. Text measurements are cached per level. It filters those placements against the current viewport before passing at most 256 candidates to collision placement, and keeps at most 64 pooled text elements with CSS ring/leader marks. Four fixed alternatives reserve the whole plate, dot ring and leader at actual screen coordinates; they exclude the card, Recent strip, minimap and existing overlay rectangles. Entry requires four pixels of extra clearance; a surviving name can retain its side without that extra clearance. The existing sticky zoom level controls the overview budget. There is no per-frame graph traversal, sorting or text measurement in this path; the bounded collision pass and style updates do run on drawn frames, including lens/radius animation. Names can appear or disappear as room opens or closes, never as unexplained fractional opacity. The canvas remains on-demand, not a permanent animation loop.

There is no new spatial index or ranking authority. The original globally degree-ranked candidate collection and its grid placements remain shared with Ranked; Anchored no longer truncates that collection to the first 256 global nodes. Offscreen placements cannot consume the 256-entry collision allowance. As with Ranked, this is not viewport-complete naming; hover names take priority and the connection card still provides navigation. Collisions with *unlabelled* dots and graph edges are not globally solved. Independent review, browser-native software-WebGL evidence and hardware-GPU acceptance remain distinct; see the benchmark record for measured costs and limitations.

## Dense focus and overview insets (2026-11-16)

The existing direct-label budget (24) is also the dense-hub threshold. Above it, both label styles admit at most six direct names and discard secondary label tiers before measurement; hover retains its priority slot. Canvas and WebGL suppress blanket direct rings at the same threshold while keeping the focus ring. Anchored retains its named-dot marks. No notes, edges, connection-card rows, positions or picking targets are removed. Anchored remains the default and Ranked remains selectable; no second density preference or layout authority is introduced.

Group overview consumes the same right-edge tools-overlap measurement as detail. Its canvas and hit coordinates use the remaining width, including during stage resize. Opening snaps out from under the panel; closing expands the canvas with a 180 ms CSS width transition, disabled by reduced motion. ResizeObserver redraws only when canvas or container size changes, and disposal disconnects it. A panel that occupies nearly the entire narrow view leaves the canvas nearly hidden rather than painting groups behind the panel; the existing Members list remains the navigation surface there. This does not claim readable canvas groups at arbitrarily small available widths or solve global graph density.

## Haze and fitting review (2026-11-15)

WebGL edge picking applies the same stable line rank and long-line threshold as the context-line ink budget. Omitted lines cannot acquire hover just because the pointer crosses their invisible geometry; already hovered, focused and path lines retain the shader's exemptions. Canvas keeps its union-stroke behavior. The bounded incident-edge picker remains the only edge hit-test authority; no GPU readback is added.

Fit all counts currently visible connected notes before sampling, respecting filtered endpoints, Only connections and hidden types. At eight or more it frames the connected population; below eight it frames all visible notes. Sampling is by eligible population rather than absolute node IDs, capped at 8,192 sampled positions plus collapsed hubs. Connectivity is scanned only for explicit fitting, not per frame. Synthetic compiled-renderer regressions cover sparse filters, the threshold, hidden types and ink picking; no new native performance or visual acceptance is claimed.

## Density edge compositing (2026-11-16 addendum)

`visuals.edgeCompositing` selects the unchanged Blend drawing (default) or an optional density pass. Admission, long-line thresholds, positions, ranking and picking remain shared. Context edges render quarter-scaled premultiplied RGBA into one additive RGBA8 target. A fullscreen quad recovers weighted endpoint color and maps accumulated alpha `d` to `min(.9, .2*d + .8*d*d/(1+d*d))`. This increases bundle-to-single contrast rather than scaling every line equally. RGBA8 saturation falls back to the configured edge color so clipped channels cannot whiten dense pixels. The existing endpoint gradient is not a new palette or grouping authority. Focus/hover/path strokes retain the same shader equations in a separate source-over pass above context; the existing Only connections layer order remains intact.

The target is lazy, reused until CSS size changes, bounded to 2048 pixels per side and at most 16 MiB. Rendering at CSS resolution deliberately avoids DPR-squared allocation; compositing restores the full drawing-buffer viewport and premultiplied source-over. No `EXT_color_buffer_float` dependency exists. Incomplete framebuffer or allocation errors select Blend for that size, with resize/restoration allowing another attempt. Context restoration resets the stale target, texture and size state; disposal deletes the framebuffer through the renderer's existing resource lifetime. Canvas retains its existing line-share/union-stroke fallback, disclosed in the setting. No CPU edge scan, pixel readback, new core authority, dependency or worker path is introduced. Deterministic tests exercise mode persistence, curve bounds, tier splitting, draw/target counts, failure caching, resource cleanup and Canvas fallback; they are not hardware-driver acceptance.

## Relationship-panel recovery

A native large-literal reproduction on untouched slice-2 `f24c75de` proved an existing race: a metadata refresh advanced the active revision to 2 while the retained detail dictionary still belonged to revision 1. A contribution read was rejected by the worker, the view silently swallowed the error, and the subsequent group redraw erased the selection.

A selected pair is now a durable in-view intent, not a disconnected panel node or a reused pair of dictionary indices. Local group summaries include an optional raw dictionary `key`, so a pending click can be retained before detail arrives without conflating equal-looking typed labels. Reads wait for active, group and detail generations to match. Fresh matching generations rebind the raw values to their new IDs and request the page once; stale successes and failures are ignored. Removed keys/pairs report a visible explanation rather than selecting a different relationship. Loading, refreshing, empty and failed reads are explicit, with user-triggered Retry. Source/group-definition changes, explicit navigation and closure clear the intent. Keys are captured synchronously from the exact graph the user clicked, never from a later summary with reused numeric IDs. Legacy keyless selections retain only their original display labels and remain refreshing until a fresh keyed summary resolves each label unambiguously; missing/duplicate labels are never guessed. Cached paints use a separate negative generation identity, never the live revision. Binary cache format 3 rejects/quarantines slice-2 format-2 summaries and rebuilds from public metadata. The review probe with shifted IDs under the same live revision is a regression test.

## Graduated connection highlighting (2026-11-14 addendum)

The one-hop binary hover flag becomes topological tiers computed by a pure main-realm helper (`focusTiers`, beside `incidentEdges`): focus and direct = 255, neighbours of neighbours = 128, rest = 0, by minimum hop over type-visible edges between filter-visible nodes. An edge note's own relationship rows are transparent. Node tiers occupy the existing state-texture G byte; edge tiers are one byte per edge on instanced attribute 3. Both WebGL shaders and the Canvas path read those same bytes, so there is no second emphasis authority. The focus source is the hovered note, else the selected note. Work happens only when that source or the view masks change: hop 1 is complete; hop 2 is capped at 65,536 scanned incident entries in CSR order and reports truncation. Weights multiply alpha within premultiplied source-over (direct edges `min(1, 3a)`, context edges `a`, rest unchanged from the earlier dim rule), so emphasis cannot saturate toward white, and the zero-edge-opacity contract is unchanged. Semantic ancestor or framework tiers are not inferred; they require a future declared, ontology-neutral relationship-role binding. This addendum adds no setting, worker request, layout or persistence path.

## Consequences and evidence

The renderer itself adds no runtime package. The complete shipped layout stack still audits five MIT packages, not the plan's one-package intermediate aspiration and not zero dependencies. Slice-3 bundle ceilings are enforced at 250,000 minified bytes and 70,000 gzip bytes; the later 150,000/45,000 targets remain recorded, not claimed as met.

Tests cover packed picking against a brute-force oracle, malformed coordinates, texture padding, incident edges, label collisions/LOD, color validation, settings migration, generation waits, raw-key reordering, stale promises and explicit retry. Synthetic native lanes cover actual click-open, group/detail/hover/selected screenshots in host light/dark themes, no-worker palette refresh, software fallback and hardware context restoration. The large-literal regression repeats the original first-click path and refreshes the selection. Browser measurements distinguish default group open, detail initialization, full verified memory-backed warm open, main-realm retained heap and pan/zoom frames. Exact counts and receipts belong to the benchmark record; native FPS, integrated/mobile drivers and all-scale readability remain separate gaps.


## Connection lens (2026-11-15 addendum)

A temporary renderer-only lens pins one focus and places its visible direct connections into ordered CSS-pixel rings. Incident CSR traversal includes transparent relationship-note rows and respects type/filter/collapse masks. Type/name sorting and text measurement are cached per target/view; geometry is linear in the direct connections and radius buckets bound zoom-driven reflow. A sparse RGBA32F override texture stores ring offsets and an enabled bit. The shared shader position function blends the unchanged display-position texture toward those offsets with one uniform; CPU Canvas, overlays and picking use the same coordinate equation. Picking excludes displaced nodes from their old grid locations and tests the sparse override set. Lens texture updates coalesce into one span per touched texture row rather than one driver call per node. Budgeted edge picking visits nearby unchanged endpoints before spending its remaining budget on the displaced cloud. Card framing uses the same effective coordinates; CSS-pixel rings larger than the viewport still require panning. No worker/core/layout persistence changes occur. Returning the old ring before retargeting avoids stale overrides; reduced motion uses the same endpoints instantly. ## Interest ranking (2026-11-15 addendum)

Which direct connections get label slots, card rows and lens places is decided by a pure degree-of-interest scorer (`src/interest.ts`): inverse degree, an optional declared numeric column (rank-normalised in the core projection, presentation only, outside layout identity), a recency boost from the card's visit trail and an optional bridge bonus for a different group. Hop distance carries a weight larger than every other term together, so the fixed tier precedence is preserved. The renderer memoises one scorer per focus, trail, grouping and setting; scores are lazy per node, so ordering costs O(degree log degree) and nothing runs per frame. No ontology keys are named.

## Context menu and click-to-focus (2026-11-15 addendum)

Menus live in `src/context-menu.ts` and reach the renderer only through `RendererControls`. Menu entries are registry actions (`menu: true`), so keys and menus share one list; the Obsidian `Menu` and `file-menu` event sit behind a host presenter seam set by the view, so the module stays testable without Obsidian. Focus is click-only (wave 5, superseding the earlier timed preview): `setHover` only moves the hovered note's ring and name, and `emphasize` takes the focus from the lens or the selection, so hover never retiers and there is no timer or override state. Long-press uses one timer per view, cancelled by the existing drag threshold, a second pointer or release, and swallows the following tap. No per-frame or O(nodes) work is added.

## Path finder (2026-11-15 addendum)

"How are these connected?" is renderer-only. A pure bidirectional BFS (`src/path-finder.ts`) walks the existing incident CSR within the type, filter and render-visible masks, expanding the smaller frontier level by level; the first meeting is a shortest path. It stops at 6 steps or 200,000 scanned incident entries and reports which limit ended it, never a partial path. Relationship-note rows are transparent: a dot and its two owned rows form one step. Alternates block every earlier inner note, dot and row, so they are node-disjoint (at most 3). The path reuses the selected-relationship tier mode: its rows get edge byte 253 (above the 255/254 focus tiers, never legend-masked) and its notes the direct byte, so WebGL and Canvas share one byte authority; the shader branch and Canvas pass use the same `pathStroke` terms. Endpoint rings, hop badges and the hop list are bounded text-only DOM overlays. No worker, core or layout changes. Unit and compiled-renderer seams do not establish GPU rasterization or native visual acceptance.

## Importance-ranked overview (2026-11-15 addendum)

Renderer-local edge quantiles replace the uniform hash rank. On view changes, eligible rows are ordered by a stable hash divided by a weight from endpoint degree, declared normalized interest and differing group codes. Quantiles preserve the eligible line-share count; the existing screen-length threshold can only reduce it. Camera frames do no sorting. Canvas, WebGL and picking consume one uint32 rank column, with focus, path and hover exemptions; core and worker columns remain authoritative. The existing geometry-derived line share receives an overview allowance of clamp(8 × camera/home ratio, 1, 8), capped at all eligible rows; it returns to the original share at home/8 and closer. This makes the dot-dense overview less aggressively sampled without introducing another budget authority. Retained adaptive context lines use constant unthinned opacity, with no close-zoom opacity boost: the first candidate retained that boost and exceeded the historical near-view edge-added luminance. Legacy zoom-adapt base radius has a 1.2 CSS-pixel minimum capped by the requested radius; predictable sizing is unchanged. Overview glyph quads supply a surface plate, gated by the existing label-plates setting, instead of four outline texture fetches. Canvas uses cached label widths, not per-frame measurement. Renderer paths share admission and emphasis policy, not identical rasterization: Canvas still unions straight strokes; WebGL uses its existing curved/color-interpolated path.

## Continuous relationships and pan-stable marks (2026-11-16 addendum)

The screen-space budget admits relationships, not arbitrary halves of paths through relationship notes. Only explicit carrier-owned legs share a renderer-local rank; an unrelated inline/producer link touching a carrier stays independent. Rank quantiles are weighted by eligible row count, so grouping does not double the expected line budget. Bit 24 of the existing uint32 rank column marks these indivisible units; the low 24 bits retain the quantile. Grouped legs bypass the per-leg length threshold, and views containing carriers budget full sampled lengths rather than claiming the old length-fade discount. Hidden types and filtered endpoints stay hidden; focused/path/hover protections are unchanged. Canvas and picking use the same packed-rank predicate as WebGL.
