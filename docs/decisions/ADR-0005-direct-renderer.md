# ADR-0005: direct typed-array renderer and persistent relationship intent

Date: 2026-11-10. Status: implemented locally; exact verification and remaining targets are in [benchmarks](../benchmarks.md#slice-3-direct-renderer). Supersedes the interim detail renderer in ADR-0002 and the Sigma-specific renderer limitation in ADR-0004. It does not replace the worker layout or establish remote acceptance.

## Decision

The detail renderer consumes the engine-neutral projection and Float32 positions directly. WebGL2 draws instanced circular node quads and straight edge quads, with RG32F positions and an indexed RGBA8 color palette. Camera updates change uniforms, not graph buffers or a second object graph. Sigma and main-thread Graphology construction are removed. Graphology/FA2 remain exclusively in the existing worker layout; extracting its options prevents settings from retaining layout code in the main runtime graph. Both bundles are minified, including the worker before it is embedded as a string.

Node picking uses a packed CPU uniform grid with deterministic nearest-hit ties; nearby edge hover visits incident-edge CSR. Picking does not read pixels back from the GPU. Click navigation retains exact local-file resolution. Labels are Canvas-rasterized glyphs, never DOM markup or shader source. Degree-prioritized candidates and viewport-derived budgets feed collision-checked placements at seven conservative zoom LODs. Atlas dimensions, candidate count, string length and label count are bounded. Fonts or viewport size can rebuild placement; camera drawing does no per-frame label measurement or graph reconstruction. Label choices are global LOD subsets, not viewport-local re-ranking on every pan.

CSS variables `--graph-ng-bg|node|edge|group|text|accent|font` fall back to the host graph/background/font variables and validated defaults. Declared colors accept hex RGB/RGBA or a restricted CSS variable reference. `css-change` and color-scheme changes reread computed colors and upload the palette without worker calls, layout or graph-buffer replacement. A font change separately rebuilds glyphs. The initial 256-entry palette expands by rows for larger declarations.

Program linking uses nonblocking `KHR_parallel_shader_compile` completion queries when available, with timer yields and a deadline. Without the extension, driver link-status checks may still block; a hardware result cannot prove every driver. Painting is on demand through rAF plus one configurable `frameBackstopMs` timer (32 ms default) for embedded windows that withhold rAF. `shaderPollMs` defaults to 8 ms; camera bounds and label-candidate multiplier are settings too. It is not a continuous background animation loop. Context loss retains CPU arrays and disables drawing/hit interaction; restoration recompiles/reuploads. If restoration does not complete within `contextRestoreTimeoutMs` (5 seconds by default), or fails, the view switches to bounded Canvas detail or groups. Disposal removes listeners, cancels timers, explicitly loses its WebGL context and prevents failed restoration from reopening a disposed view.

Paged Canvas2D groups remain the primary overview. Software-only detail is allowed within both validated `canvasMaxDetailNodes` / `canvasMaxDetailEdges` budgets, default 2,000 visible nodes / 10,000 visible edges. Eligible edge indices are prepared once; frame drawing does not scan every hidden edge or truncate excess relationships. Larger views retain groups and member lists with a visible fallback notice. The plan's proposed 20,000-node default is deferred: the native software proof reaches 600/1,400, not 20,000 nodes, and even the conservative refusal boundary is not a measured FPS guarantee.

## Haze and fitting review (2026-11-15)

WebGL edge picking applies the same stable line rank and long-line threshold as the context-line ink budget. Omitted lines cannot acquire hover just because the pointer crosses their invisible geometry; already hovered, focused and path lines retain the shader's exemptions. Canvas keeps its union-stroke behavior. The bounded incident-edge picker remains the only edge hit-test authority; no GPU readback is added.

Fit all counts currently visible connected notes before sampling, respecting filtered endpoints, Only connections and hidden types. At eight or more it frames the connected population; below eight it frames all visible notes. Sampling is by eligible population rather than absolute node IDs, capped at 8,192 sampled positions plus collapsed hubs. Connectivity is scanned only for explicit fitting, not per frame. Synthetic compiled-renderer regressions cover sparse filters, the threshold, hidden types and ink picking; no new native performance or visual acceptance is claimed.

## Density edge compositing (2026-11-16 addendum)

`visuals.edgeCompositing` selects the unchanged Blend drawing (default) or an optional density pass. Admission, long-line thresholds, positions, ranking and picking remain shared. Context edges render quarter-scaled premultiplied RGBA into one additive RGBA8 target. A fullscreen quad recovers weighted endpoint color and maps accumulated alpha `d` to `min(.9, .2*d + .8*d*d/(1+d*d))`. This increases bundle-to-single contrast rather than scaling every line equally. RGBA8 saturation falls back to the configured edge color so clipped channels cannot whiten dense pixels. The existing endpoint gradient is not a new palette or grouping authority. Focus/hover/path strokes retain the same shader equations in a separate source-over pass above context; the existing Only connections layer order remains intact.

The target is lazy, reused until CSS size changes, bounded to 2048 pixels per side and at most 16 MiB. Rendering at CSS resolution deliberately avoids DPR-squared allocation; compositing restores the full drawing-buffer viewport and premultiplied source-over. No `EXT_color_buffer_float` dependency exists. Incomplete framebuffer or allocation errors select Blend for that size, with resize/restoration allowing another attempt. Context restoration resets the stale target, texture and size state; disposal deletes the framebuffer through the renderer's existing resource lifetime. Canvas retains its existing line-share/union-stroke fallback, disclosed in the setting. No CPU edge scan, pixel readback, new core authority, dependency or worker path is introduced. Deterministic tests exercise mode persistence, curve bounds, tier splitting, draw/target counts, failure caching, resource cleanup and Canvas fallback; they are not hardware-driver acceptance.

## Relationship-panel recovery

A native large-literal reproduction on untouched slice-2 `f24c75de` proved an existing race: a metadata refresh advanced the active revision to 2 while the retained detail dictionary still belonged to revision 1. A contribution read was rejected by the worker, the view silently swallowed the error, and the subsequent group redraw erased the selection.

A selected pair is now a durable in-view intent, not a disconnected panel node or a reused pair of dictionary indices. Local group summaries include an optional raw dictionary `key`, so a pending click can be retained before detail arrives without conflating equal-looking typed labels. Reads wait for active, group and detail generations to match. Fresh matching generations rebind the raw values to their new IDs and request the page once; stale successes and failures are ignored. Removed keys/pairs report a visible explanation rather than selecting a different relationship. Loading, refreshing, empty and failed reads are explicit, with user-triggered Retry. Source/group-definition changes, explicit navigation and closure clear the intent. Keys are captured synchronously from the exact graph the user clicked, never from a later summary with reused numeric IDs. Legacy keyless selections retain only their original display labels and remain refreshing until a fresh keyed summary resolves each label unambiguously; missing/duplicate labels are never guessed. Cached paints use a separate negative generation identity, never the live revision. Binary cache format 3 rejects/quarantines slice-2 format-2 summaries and rebuilds from public metadata. The review probe with shifted IDs under the same live revision is a regression test.

## Graduated connection highlighting (2026-11-14 addendum)

The one-hop binary hover flag becomes topological tiers computed by a pure main-realm helper (`focusTiers`, beside `incidentEdges`): focus and direct = 255, neighbours of neighbours = 128, rest = 0, by minimum hop over type-visible edges between filter-visible nodes. An edge note's own relationship rows are transparent. Node tiers occupy the existing state-texture G byte; edge tiers are one byte per edge on instanced attribute 3. Both WebGL shaders and the Canvas path read those same bytes, so there is no second emphasis authority. The focus source is the hovered note, else the selected note. Work happens only when that source or the view masks change: hop 1 is complete; hop 2 is capped at 65,536 scanned incident entries in CSR order and reports truncation. Weights multiply alpha within premultiplied source-over (direct edges `min(1, 3a)`, context edges `a`, rest unchanged from the earlier dim rule), so emphasis cannot saturate toward white, and the zero-edge-opacity contract is unchanged. Semantic ancestor or framework tiers are not inferred; they require a future declared, ontology-neutral relationship-role binding. This addendum adds no setting, worker request, layout or persistence path.

## Consequences and evidence

The renderer itself adds no runtime package. The complete shipped layout stack still audits five MIT packages, not the plan's one-package intermediate aspiration and not zero dependencies. Slice-3 bundle ceilings are enforced at 250,000 minified bytes and 70,000 gzip bytes; the later 150,000/45,000 targets remain recorded, not claimed as met.

Tests cover packed picking against a brute-force oracle, malformed coordinates, texture padding, incident edges, label collisions/LOD, color validation, settings migration, generation waits, raw-key reordering, stale promises and explicit retry. Synthetic native lanes cover actual click-open, group/detail/hover/selected screenshots in host light/dark themes, no-worker palette refresh, software fallback and hardware context restoration. The large-literal regression repeats the original first-click path and refreshes the selection. Browser measurements distinguish default group open, detail initialization, full verified memory-backed warm open, main-realm retained heap and pan/zoom frames. Exact counts and receipts belong to the benchmark record; native FPS, integrated/mobile drivers and all-scale readability remain separate gaps.


## Connection lens (2026-11-15 addendum)

A temporary renderer-only lens pins one focus and places its visible direct connections into ordered CSS-pixel rings. Incident CSR traversal includes transparent relationship-note rows and respects type/filter/collapse masks. Type/name sorting and text measurement are cached per target/view; geometry is linear in the direct connections and radius buckets bound zoom-driven reflow. A sparse RGBA32F override texture stores ring offsets and an enabled bit. The shared shader position function blends the unchanged display-position texture toward those offsets with one uniform; CPU Canvas, overlays and picking use the same coordinate equation. Picking excludes displaced nodes from their old grid locations and tests the sparse override set. Lens texture updates coalesce into one span per touched texture row rather than one driver call per node. Budgeted edge picking visits nearby unchanged endpoints before spending its remaining budget on the displaced cloud. Card framing uses the same effective coordinates; CSS-pixel rings larger than the viewport still require panning. No worker/core/layout persistence changes occur. Returning the old ring before retargeting avoids stale overrides; reduced motion uses the same endpoints instantly. Existing label budgets, context positions and Canvas refusal limits remain unchanged. Unit/driver seams do not establish GPU rasterization, large-graph FPS or native visual acceptance.

## Equivalent CPU work reduction (2026-11-15 addendum)

Focus ranking buckets the existing tiers and sorts only tiers that can fill the candidate cap. The existing dense-hub policy (>50 direct connections, no secondary labels) is applied before interest scoring and text measurement rather than immediately before radial placement. Full-sort/post-filter oracle tests preserve tier precedence, score/degree order, ID ties, carrier exclusions, direct counts and cap semantics. Canvas base radius and camera invariants are evaluated once per synchronous draw; minimap density uses equivalent scalar coordinates instead of per-node tuples. These changes introduce no new projection, setting, worker path or visibility policy. Declared-key group dictionaries reuse canonical core columns through independent copies, not shared mutable ownership. CPU-only compiled-renderer/worker evidence and startup limitations are recorded in [benchmarks](../benchmarks.md#bounded-cpu-performance-pass--2026-11-15); independent merge review and native/GPU acceptance remain separate.

## Interest ranking (2026-11-15 addendum)

Which direct connections get label slots, card rows and lens places is decided by a pure degree-of-interest scorer (`src/interest.ts`): inverse degree, an optional declared numeric column (rank-normalised in the core projection, presentation only, outside layout identity), a recency boost from the card's visit trail and an optional bridge bonus for a different group. Hop distance carries a weight larger than every other term together, so the fixed tier precedence is preserved. The renderer memoises one scorer per focus, trail, grouping and setting; scores are lazy per node, so ordering costs O(degree log degree) and nothing runs per frame. No ontology keys are named.

## Context menu and click-to-focus (2026-11-15 addendum)

Menus live in `src/context-menu.ts` and reach the renderer only through `RendererControls`. Menu entries are registry actions (`menu: true`), so keys and menus share one list; the Obsidian `Menu` and `file-menu` event sit behind a host presenter seam set by the view, so the module stays testable without Obsidian. A relationship's note path comes from the existing bounded `relationships` worker request, only for rows that have a carrier. Focus is click-only (wave 5, superseding the earlier timed preview): `setHover` only moves the hovered note's ring and name, and `emphasize` takes the focus from the lens or the selection, so hover never retiers and there is no timer or override state. Long-press uses one timer per view, cancelled by the existing drag threshold, a second pointer or release, and swallows the following tap. No per-frame or O(nodes) work is added.

## Path finder (2026-11-15 addendum)

"How are these connected?" is renderer-only. A pure bidirectional BFS (`src/path-finder.ts`) walks the existing incident CSR within the type, filter and render-visible masks, expanding the smaller frontier level by level; the first meeting is a shortest path. It stops at 6 steps or 200,000 scanned incident entries and reports which limit ended it, never a partial path. Relationship-note rows are transparent: a dot and its two owned rows form one step. Alternates block every earlier inner note, dot and row, so they are node-disjoint (at most 3). The path reuses the selected-relationship tier mode: its rows get edge byte 253 (above the 255/254 focus tiers, never legend-masked) and its notes the direct byte, so WebGL and Canvas share one byte authority; the shader branch and Canvas pass use the same `pathStroke` terms. Endpoint rings, hop badges and the hop list are bounded text-only DOM overlays. No worker, core or layout changes. Unit and compiled-renderer seams do not establish GPU rasterization or native visual acceptance.


## Connection navigator (2026-11-15 addendum)

The card derives a temporary presentation index from existing incident-edge connection groups. It deduplicates notes under current declared numeric group codes (equal-looking group labels remain distinct), preserves all relationship directions and uses a bounded public metadata-cache `title` only for display. Existing path-derived names remain the fallback and navigation authority; no identity, schema, worker, core or persistence change occurs. Filtering scans this per-card index and never reruns topology or metadata lookup. Group headers page by 100 and expanded sections by 50; explicit limits remain visible. Hub disclosure (>50 direct connections) starts collapsed, while `+N more` opens the largest group and focuses its input at scroll origin without camera motion. Text-editing keys stay inside the input.

The graph supplies orientation rather than a hub directory: above 50 direct connections it caps direct labels at six, omits secondary labels and suppresses direct contrast rings and the optional extra strong-edge boost in both Canvas and WebGL. The common tier bytes, focus ring, declared group authority, settings and ordinary topological emphasis are unchanged. Opaque top-left controls stack above labels. This is a presentation policy, not a new projection or security boundary. Synthetic source-renderer Canvas captures and compiled-bundle tests do not establish native host, hardware-WebGL, mobile or 16k-note performance acceptance.

Merged additions (tournament round 1). A lone navigator section opens by itself. When a hub has some, but not all, sections open, `discloseTiers` (`src/hub-disclosure.ts`) rewrites only the already computed tier bytes so that just those sections' notes, the focus and owned carrier dots on resolved routes stay lit; a per-section "Neighbours of neighbours" toggle re-admits that section's second hop from the existing bounded `focusTiers` result, never a new traversal. The touched lists are compacted afterwards so labels, legend counts, pips and the next reset see only lit notes. Label overlap is decided by whole rectangles (`overlapsBox`) against the docked card and cached panel rectangles (Recent/legend stack, minimap); panel rectangles come from a ResizeObserver and `resize()`, and the hover label is measured once per caption change, so drawing adds no layout reads. The hover label tries right, left, above and below; "+N more" counts the direct labels actually shown that frame. Evidence is a compiled-bundle test on a synthetic top-left hub fixture plus a browser DOM-rectangle check of the real source renderer (Canvas2D); it is not native-host or hardware-WebGL acceptance.


## Anchored neighbourhood (2026-11-15 addendum)

Replace temporary recentering connection isolation with an anchored ego network (reach 0–3) and an ordered set of explicitly expanded frontier nodes. `neighbourhood` reuses the incident CSR and owned-carrier traversal in `src/connection-card.ts`; its single mask intersects the host filter and type visibility before `applyView`, so Canvas, WebGL, picking and search share the existing visibility authority. Expansions disconnected by a filter change are ignored; hiding the anchor exits the mode. Reach changes clear expansions. Travel to a hidden note adds only that note (and its linking relationship-note dot) while it is adjacent to the region; a history jump outside the region exits it rather than silently moving the anchor. Traversal and frontier counting share a 200,000 scanned-incident-row budget, including carrier fan-out; partial work is labelled and an incomplete frontier count is never presented.

Topology work occurs on mask changes, not hover or draw. At most 24 frontier DOM buttons are projected per frame, with cached count-derived width and 32-pixel height and cached panel/card collision checks; all frontier nodes remain expandable through the card. Admitted nodes use normal opacity in both renderer paths; focus rings, labels and tiers still indicate selection. Expansion preserves positions, camera and selection, and Canvas refusal (a typed `CanvasLimit` from `canvasDetailEdges`) restores the previous neighbourhood state. The chip joins the existing observed top-left stack rather than adding a competing overlay system. No core, worker, declaration, dependency or persistence change. Synthetic browser Canvas/SwiftShader evidence and deterministic tests are not native-host, hardware-GPU, mobile or 16k-node frame-time acceptance.


## Importance-ranked overview (2026-11-15 addendum)

Renderer-local edge quantiles replace the uniform hash rank. On view changes, eligible rows are ordered by a stable hash divided by a weight from endpoint degree, declared normalized interest and differing group codes. Quantiles preserve the eligible line-share count; the existing screen-length threshold can only reduce it. Camera frames do no sorting. Canvas, WebGL and picking consume one uint32 rank column, with focus, path and hover exemptions; core and worker columns remain authoritative. The existing geometry-derived line share receives an overview allowance of clamp(8 × camera/home ratio, 1, 8), capped at all eligible rows; it returns to the original share at home/8 and closer. This makes the dot-dense overview less aggressively sampled without introducing another budget authority. Retained adaptive context lines use constant unthinned opacity, with no close-zoom opacity boost: the first candidate retained that boost and exceeded the historical near-view edge-added luminance. Aggregate/group rendering and Adapt-to-zoom opt-out retain their previous alpha formula.

Strong focus uses a continuous inverse-square-root target with a .18 floor instead of switching off above 50 direct connections. Both paths use uniform focus strokes, removing the extra source-to-target ramp (the explicit edge-direction setting is unchanged). The direct-label/ring hub limits remain. Legacy zoom-adapt base radius has a 1.2 CSS-pixel minimum capped by the requested radius; predictable sizing is unchanged. Overview glyph quads supply a surface plate, gated by the existing label-plates setting, instead of four outline texture fetches. Canvas uses cached label widths, not per-frame measurement. Renderer paths share admission and emphasis policy, not identical rasterization: Canvas still unions straight strokes; WebGL uses its existing curved/color-interpolated path.

Deterministic regression evidence does not establish hardware GPU, mobile or real-vault acceptance. Synthetic before/after measurements are recorded in docs/benchmarks.md: mid-label and hub-fan improvements do not resolve the fit-all dot-ball gap. Independent review remains a separate requirement.

## Small-mark labels, isolated fans and view restoration (2026-11-15 addendum)

Zoom-adaptive labels retain the highest-ranked names when base dots become tiny: the former global opacity cutoff becomes a tighter rank cutoff. Opting out of adaptive labels preserves the existing size threshold. Every atlas quad carries its whole label's bounds, so WebGL rejects the whole annotation, not individual clipped glyphs; Canvas and bounded DOM annotations apply the same own-height viewport inset. Focus hover labels and the disclosure button can move inward; annotations that cannot fit are hidden. Plates remain one quad per label in the existing atlas pass.

Only connections places its existing edge pass after opaque nodes while a focus is active, in both renderer paths; ordinary graph layering is unchanged. No extra edge pass is added. Rank rejection now precedes shader texture/curve work where possible. A top-decile cross-group bridge receives a 10% admission-rank discount during view-time ranking, not a per-line opacity increase or a camera-time edge scan. This slightly expands admission, superseding the earlier exact-quantile-count statement; the long-line threshold still only reduces it. Compiled GL-driver tests guard endpoint/degree columns against per-frame scans and check pass counts and cached-rank identity.

Escape clears pointer replay and the hover animation cache as well as selection. Breadcrumb history remains navigable but only the actual selection can be marked current. The host view serializes a validated `nodes`/`groups` presentation through public `getState`/`setState` and requests workspace-layout saves on successful user presentation changes. Provisional group paints do not overwrite the requested Notes state; existing software-renderer refusal limits still apply. This persists presentation, not selection, camera, topology or a second projection. Synthetic native measurements and their remaining performance/restoration limits are recorded in the benchmark record.
