# ADR-0004: worker pipeline and disposable binary generations

Date: 2026-11-10. Status: implemented locally; benchmark and native evidence are recorded separately. Supersedes slice-1 JSON layout persistence and declaration v1 output, not the public-API or ontology-neutral boundaries.

## Decision

A plugin-lifetime Blob Web Worker owns projection, CSR construction, group contraction, canonical digests, topology hashes, layout and binary serialization. The adapter reads only public `metadataCache` entries and declared frontmatter properties. It does not scan bodies, touch host storage internals or persist a property/fact-row database. Its worker input is bounded UTF-8 dictionaries, declared value columns and producer-link CSR, transferred rather than cloned. Later events send dirty paths only. Every request and response carries a revision; stale responses cannot replace a newer view. All RPCs, including member/contribution reads, queue and validate the projection revision. A per-request processing deadline starts on worker acknowledgement, not while queued, with a separate dispatch watchdog. Worker failures restart at most a configurable two times per plugin lifetime, discard old RPCs and force complete live reingestion rather than replay detached buffers. Cancelled ingestion retains unacknowledged dirty paths, invalidates coverage and forces a full reload.

The main realm yields after configurable row/time budgets (2,000 rows / 8 ms by default). Group summaries arrive before detail buffers and layout. Contributions are fetched one page at a time. Graphology node/edge creation is cooperatively sliced; Sigma's own synchronous indexing/upload remains an acknowledged limit until the renderer replacement. Position snapshots transfer every configurable five iterations, with returned buffers reused when the group view no longer needs them. The interim public FA2 batching reinitializes its integrator history between batches; `stream-v2` is a distinct producer, not a claim of bit-identical slice-1 coordinates.

## Storage and scope

`data.json` contains `{settings}` only. The separate default location is the plugin's `cache/local/` directory. A configurable subdirectory is confined to this plugin's own `cache/` location; arbitrary vault paths are refused. Nonlocal source tags receive a digest namespace. The host-facing `setSourceIdentity()` hook takes an opaque member/view identity, clears the displayed old view and discards its old namespace before rebuilding. No server or shared-room adapter is implemented, and this hook alone does not establish a remote authorization boundary. A future host must supply the actual view identity and nonreplicated storage policy, not infer authority from plugin IDs or a user-editable setting.

Each generation is labelled with format, declaration digest, layout parameters/digest, iteration-stream tuning, group level, producer including host API identity, source/view identity and generation key. Source/producer/layout/format mismatches are refused, including warm starts. A complete live build checks every saved identity against current in-view identities before reuse. Unknown/removed identities quarantine the generation and rebuild without its positions.

Files are at most 1 MiB: finite manifests, a finite LRU index and chunked position Float32, identity UTF-8/offset, topology Uint32-pair and group-summary parts. Each chunk carries a SHA-256 checksum and length. Existing matching chunks are reusable after an interrupted write; the manifest and then LRU index are the commit points. Readers bound file sizes before reads/parsing, reject missing/truncated/oversized/nonfinite/malformed content and quarantine rather than ask for manual cache repair. Retention uses `cachedDeclarations`; kept/removed/quarantined actions have a bounded in-memory trace. Incomplete, uncommitted directories are not accepted as generations. Failed partial writes and derived quarantines are pruned under configurable artifact/byte caps (8 / 256 MiB by default); only cache-owned data is eligible for bounded deletion where portable directory trash is unavailable. Source/settings quarantines are excluded. Cache files are disposable derived data, not backups or source authority.

Slice-1 active-layout data is accepted once as a bounded migration input, encoded by the worker and rewritten in the new location. Legacy source/format information cannot establish freshness; migration is local-only, cleared on source identity changes, and only a warm-position hint followed by live identity validation. Invalid settings are copied to timestamped quarantine before defaults are saved, with a notice; failed copies prevent fallback writes. Settings version 2 records a one-time upgrade from legacy unlimited aggregate counts to finite defaults; later explicit unlimited counts remain opt-in. Large legacy JSON still incurs its one-time host JSON decode, within the settings byte budget.

## Cached paint and verification

The last compatible group summary can paint before metadata is ready, explicitly labelled `cached · verifying N of M`. Member lists and filters are provisional until each Markdown file has a non-null public cache entry. Repeated `resolved` events alone are not readiness. Partial graphs do not overwrite complete persisted generations. After live verification an equal generation key restores positions; a changed key rebuilds or uses compatible in-view warm hints. No persisted frontmatter bypass is introduced.

External aggregate files have finite default byte/group/pair/carrier limits and remain labelled **unverified external aggregate**; they never merge into local rows. The headless export labels its caller-supplied one-view input and writes only to the explicit command-line destination. There is no in-app export or automatic vault export.

## Declaration compatibility

Declaration v2 uses `sourceProperty`, `targetProperty`, `typeProperty`; v1 is migrated on input and never emitted by settings saves. Folder prefixes accept strings or path-segment arrays. Persisted declaration prefixes use segments so ordinary long nested paths do not resemble opaque credentials to conservative settings-sharing scanners. This does not weaken that scanner, permit credentials, or guarantee that every arbitrary user string is shareable. A single long opaque folder segment can still be refused by the host.

## Consequences and evidence

No new runtime dependency or nonpermissive code is added. Tests cover columnar/object equivalence, yields, worker revisions, cache scope/format/identity refusal, binary corruption and lifecycle, v1 migration, path-segment boundaries and the reported scanner compatibility cases. Final single-run browser evidence at 60,600 notes: cold groups **415/458 ms**, full verified warm Sigma frames **799/970 ms**, meeting ≤500 ms / ≤1 s; no ≥50 ms tasks observed during default group open. **Detail and warm Sigma initialization still have 244–360 ms tasks: a known miss pending the slice-3 renderer.** Warm uses a new worker and memory-backed disk, not physical disk/app restart; timing-origin/heap comparison caveats remain. Post-review rerun: **391/460 ms** cold groups / **807/961 ms** full warm, again met; remaining detail/warm tasks 247–318 ms. Final member-index consumption checks the requested generation against both active groups and their detail dictionary, including the group-before-detail window; its narrow follow-up has build and 65-test coverage, not another browser/native rerun. Exact commands and performance gaps belong in [benchmarks](../benchmarks.md); unit success is not native, mobile, integrated-GPU or remote-scope acceptance.
