# ADR-0004: worker pipeline and disposable binary generations

Date: 2026-11-10. Status: implemented locally; benchmark and native evidence are recorded separately. Supersedes slice-1 JSON layout persistence and declaration v1 output, not the public-API or ontology-neutral boundaries.

## Decision

A plugin-lifetime Blob Web Worker owns projection, CSR construction, group contraction, canonical digests, topology hashes, layout and binary serialization. The adapter reads only public `metadataCache` entries and declared frontmatter properties. It does not scan bodies, touch host storage internals or persist a property/fact-row database. Its worker input is bounded UTF-8 dictionaries, declared value columns and producer-link CSR, transferred rather than cloned. Later events send dirty paths only. Every request and response carries a revision; stale responses cannot replace a newer view. All RPCs, including member/contribution reads, queue and validate the projection revision. A per-request processing deadline starts on worker acknowledgement, not while queued, with a separate dispatch watchdog. Worker failures restart at most a configurable two times per plugin lifetime, discard old RPCs and force complete live reingestion rather than replay detached buffers. Cancelled ingestion retains unacknowledged dirty paths, invalidates coverage and forces a full reload.

The main realm yields after configurable row/time budgets (2,000 rows / 8 ms by default). Group summaries arrive before detail buffers and layout. Contributions are fetched one page at a time. Graphology node/edge creation is cooperatively sliced; Sigma's own synchronous indexing/upload remains an acknowledged limit until the renderer replacement. Position snapshots transfer every configurable five iterations, with returned buffers reused when the group view no longer needs them. The interim public FA2 batching reinitializes its integrator history between batches; `stream-v2` is a distinct producer, not a claim of bit-identical slice-1 coordinates.

## Storage and scope

`data.json` contains `{settings}` only. The separate default location is the plugin's `cache/local/` directory. A configurable subdirectory is confined to this plugin's own `cache/` location; arbitrary vault paths are refused. Nonlocal source tags receive a digest namespace. The host-facing `setSourceIdentity()` hook takes an opaque member/view identity, clears the displayed old view and discards its old namespace before rebuilding. No server or shared-room adapter is implemented, and this hook alone does not establish a remote authorization boundary. A future host must supply the actual view identity and nonreplicated storage policy, not infer authority from plugin IDs or a user-editable setting.

Each generation is labelled with format, declaration digest, layout parameters/digest, iteration-stream tuning, group level, producer including host API identity, source/view identity and generation key. Source/producer/layout/format mismatches are refused, including warm starts. A complete live build checks every saved identity against current in-view identities before reuse. Unknown/removed identities quarantine the generation and rebuild without its positions.

Files are at most 1 MiB: finite manifests, a finite LRU index and chunked position Float32, identity UTF-8/offset, topology Uint32-pair and group-summary parts. Each chunk carries a SHA-256 checksum and length. Existing matching chunks are reusable after an interrupted write; the manifest and then LRU index are the commit points. Readers bound file sizes before reads/parsing, reject missing/truncated/oversized/nonfinite/malformed content and quarantine rather than ask for manual cache repair. Retention uses `cachedDeclarations`; kept/removed/quarantined actions have a bounded in-memory trace. Incomplete, uncommitted directories are not accepted as generations. Failed partial writes and derived quarantines are pruned under configurable artifact/byte caps (8 / 256 MiB by default); only cache-owned data is eligible for bounded deletion where portable directory trash is unavailable. Source/settings quarantines are excluded. Cache files are disposable derived data, not backups or source authority.

Slice-1 active-layout data is accepted once as a bounded migration input, encoded by the worker and rewritten in the new location. Legacy source/format information cannot establish freshness; migration is local-only, cleared on source identity changes, and only a warm-position hint followed by live identity validation. Invalid settings are copied to timestamped quarantine before defaults are saved, with a notice; failed copies prevent fallback writes. Settings version 2 records a one-time upgrade from legacy unlimited aggregate counts to finite defaults; later explicit unlimited counts remain opt-in. Large legacy JSON still incurs its one-time host JSON decode, within the settings byte budget.

## Cached paint and verification

The last compatible group summary can paint before metadata is ready, explicitly labelled `cached · verifying N of M`. Member lists and filters are provisional until each Markdown file has a non-null public cache entry. Repeated `resolved` events alone are not readiness. Partial graphs do not overwrite complete persisted generations. After live verification an equal generation key restores positions; a changed key rebuilds or uses compatible in-view warm hints. No persisted frontmatter bypass is introduced.

External aggregate files have finite default byte/group/pair/carrier limits and remain labelled **unverified external aggregate**; they never merge into local rows. The headless export labels its caller-supplied one-view input and writes only to the explicit command-line destination. There is no in-app export or automatic vault export.

### Metadata churn and provisional continuation (unreleased)

The streaming adapter retains exact equality stamps of acknowledged declared rows and their property coverage. These are ephemeral event-deduplication state, never a source of facts or a persisted property cache. Unchanged per-file notifications do not queue a rebuild; real row/readiness changes still do. Events during an unacknowledged ingestion batch remain pending, including edits that revert to a previously acknowledged value. Existing refresh serialization coalesces real changes behind an active layout, and settings apply now waits for that shared refresh to settle.

A completed provisional layout retains identity-keyed positions and edge hashes only in worker memory. Successive provisional generations with matching declaration, source, producer, layout, format and grouping can continue from them; extensive churn uses the full iteration budget while retaining coordinates rather than reseeding. Warm streams omit the iteration-zero seed. An exact verified saved generation still takes precedence over provisional hints. Source/configuration changes discard incompatible hints, persisted identity refusal/quarantine is unchanged, and incomplete generations remain ineligible for disk writes. Progress remains stage-local, not a promise that unrelated source changes share one percentage budget.

## Declaration compatibility

Declaration v2 uses `sourceProperty`, `targetProperty`, `typeProperty`; v1 is migrated on input and never emitted by settings saves. Folder prefixes accept strings or path-segment arrays. Persisted declaration prefixes use segments so ordinary long nested paths do not resemble opaque credentials to conservative settings-sharing scanners. This does not weaken that scanner, permit credentials, or guarantee that every arbitrary user string is shareable. A single long opaque folder segment can still be refused by the host.

## Consequences and evidence

No new runtime dependency or nonpermissive code is added. Tests cover columnar/object equivalence, yields, worker revisions, cache scope/format/identity refusal, binary corruption and lifecycle, v1 migration, path-segment boundaries and the reported scanner compatibility cases. Final single-run browser evidence at 60,600 notes: cold groups **415/458 ms**, full verified warm Sigma frames **799/970 ms**, meeting ≤500 ms / ≤1 s; no ≥50 ms tasks observed during default group open. **Detail and warm Sigma initialization still have 244–360 ms tasks: a known miss pending the slice-3 renderer.** Warm uses a new worker and memory-backed disk, not physical disk/app restart; timing-origin/heap comparison caveats remain. Post-review rerun: **391/460 ms** cold groups / **807/961 ms** full warm, again met; remaining detail/warm tasks 247–318 ms. Final member-index consumption checks the requested generation against both active groups and their detail dictionary, including the group-before-detail window; its narrow follow-up has build and 65-test coverage, not another browser/native rerun. Exact commands and performance gaps belong in [benchmarks](../benchmarks.md); unit success is not native, mobile, integrated-GPU or remote-scope acceptance.

## 0.5.2 finite layout preview

In-view physics apply uses a distinct `recompute` RPC on the existing projection. It validates existing layout options and computes a finite result with bounded, revision-checked transient coordinate paints, without modifying worker configuration, projection, persisted metadata or cached coordinates. Streamed frames have completed layout work; iteration-zero seeds are never published. Apply retains the prior graph until a progressed frame exists, hides captions and disables picking during transient coordinates, and keeps pan and zoom available. Failure restores the prior coordinate geometry without undoing camera movement. Ordinary rebuilds likewise retain the prior useful graph until progressed replacement coordinates exist. A stale projection revision is rejected. The view validates the full settings merge and checks captured active projection, layout, render generation and disposal state before committing settings and positions. Detail coordinates update on the existing renderer/context with fixed camera-frame bounds and retained camera/scope; Fit remains separate. No source/body reads are added. Repeated applies seed from the worker's prior completed baseline, not the last preview; ordinary refresh/cache handling remains the saved-layout authority. This is not a new engine or runtime-performance acceptance.

The explicit Apply transaction prepares renderer-owned CPU coordinate state and persists through the existing queue before synchronous same-context upload. Camera-frame bounds, renderer/context, topology and scope remain stable. Stale work is rejected; failed persisted candidates compensate latest live settings. GPU/context recovery and failed disk compensation report uncertainty.

### Same-context coordinate transaction

Apply prepares CPU coordinate-derived spatial grids, collapsed geometry, discs and label collision placement without constructing another renderer or context. Camera-frame bounds remain independent of the replaced spatial grids; camera, scope, masks, topology and explicit Fit remain separate. Transient stream uploads precede persistence but do not commit settings or worker authority. Awaited persistence precedes final synchronous upload and adoption. Zoom-out limits and minimap density bounds follow current geometry extents independently of the fixed camera frame; minimap viewport and pointer mappings retain that camera normalization. Successful adoption updates the home ratio and invalidates anchored/ranked label caches. History stepping checks semantic navigation availability before mutating its index. An Apply rejected before acquiring the working state leaves the previous status intact. Retained renderers suppress semantic open/travel/menu actions, and note-open callbacks capture their owning projection rather than a mutable view projection. Label invalidations deferred during layout resume on rollback; host metadata promotion preserves active layout progress. Missing host metadata does not block layout: a partial graph becomes usable, reports the remaining properties or links without an indefinite busy animation, and refreshes automatically when host metadata arrives. Position and atlas textures reuse storage; existing label buffers/VAOs are reused, although buffer resizing can have driver-dependent transient costs. The software path retains its original full geometry limits, not artificial two-renderer half-caps.

Preparation retains old and next coordinate-derived arrays and temporarily old/new label atlases. Nominal atlas backing is approximately 16 MiB each; this is an allocation component, not total browser/GPU peak proof. Context loss or failed GPU rollback retains last-good CPU data for existing recovery and reports uncertainty; failed disk compensation also reports uncertainty. No native latency, memory/driver, mobile, visual or density-cure acceptance is claimed. This unshipped candidate still requires independent review and all unchanged download gates.

### Explicit saved-view opening (unreleased)

Folder preparation is text-only and stores an ordinary bookmark after acknowledgement on the single settings queue. Explicit Open refuses unsupported dependencies and selected-group scope rather than invoking full settings apply. Request ownership and projection/configuration/render generations gate adoption and camera completion; a superseded request cannot restore a camera or report successful opening. Requested settings may lead the displayed worker result, and failure text states that distinction. Existing note detail admission and separate representation controls remain authoritative. This local candidate adds no runtime/native acceptance.

### Layout cache reuse (unreleased)

Saved positions are reused in three more cases. An unverified build (public metadata or producer links still resolving, as after an app reload) starts from a compatible saved generation instead of a cold layout; it still never persists, quarantines or replaces the complete generation, and the verified build applies the identity check above. A held generation stays a warm-start hint across declaration or group-level changes when source/view, producer, declared identity rules, layout settings, stream cadence and format match; changing identity properties or their precedence drops the hint because equal strings may now identify different notes, even with no edge churn. Exact reuse still requires the same declaration digest, group level and generation key, and a verified build drops a hint that names an identity absent from the view (dropped, not quarantined, because it is not this declaration's generation). A verified warm start whose edge set changed by more than half, or whose movable notes exceed half the view, runs a cold layout instead.

A layout-settings mismatch is refused without quarantine; source/view, producer and format mismatches still quarantine. A generation is written whenever the store has not committed or loaded the current key, so a superseded or failed write is retried by the next exact hit; a failed write no longer fails the drawn view. Quarantining a loaded generation clears its committed marker so a worker-level validation rejection cannot suppress the replacement write under the same key. Graph information reports **Reused saved layout**, **Reused saved layout, adjusted in N s** or **Computed layout in N s**.

Unchanged and recorded as a known miss: a removed or renamed identity still refuses the generation and recomputes from scratch. Removing that refusal for same-namespace generations would make deletions and renames warm starts; it is a boundary change that needs independent review. Evidence: `tests/layout-cache.test.ts` and the cache section of [benchmarks](../benchmarks.md).


## Hydration continuity and completion (2026-11-16 correction)

Successive provisional builds may warm from same-declaration in-memory positions. Complete builds prefer a usable saved generation, including its edge hashes for churn, even when the generation key changed while the app was closed. Interim positions are a fallback only when no saved generation survives the existing scope and identity checks. Provisional exact reuse is not a saved cache hit; a full iteration budget reports computation, not a short adjustment. Incomplete generations remain in memory only.

Notification deduplication retains the serialized declared-input length and two independently seeded 32-bit hash lanes, not the serialized row. Length differences always trigger notification even if both hash lanes collide. This is a probabilistic equality optimization, not cryptographic validation: a same-length double collision could delay an update until a differing notification or reset, but cannot modify source facts. Worker acknowledgement, in-flight edit/version handling and readiness checks are unchanged. Transient serialization can still allocate a large string for an oversized row.

Refresh callers await the pass requested by that call; callers arriving during an active pass coalesce onto one next pass. Later hydration passes do not extend an earlier save's completion promise. All passes still use the plugin serialization queue; closing the view skips queued work. This does not make a rebuild atomic with later host metadata changes.


## Optional hierarchy force and cache identity (wave 11)

`layout.force.familyPull` is finite 0 to 10 and defaults to 0. The zero/default field is omitted from canonical layout identity, including generation keys, layout hashes and saved-option compatibility. Missing fields in historical saved metadata therefore still match explicit zero after settings upgrade; the numerical off path is unchanged. Binary format, producer, source/view scope and complete identity refusal are unchanged.

Only a positive pull includes `declaration.hierarchy` in the layout declaration and its declared parent property in generation facts. Changing the force refuses incompatible layout parameters; unchanged positive settings reuse an exact generation. A parent-only edit changes the key without changing link-edge hashes. To avoid falsely pinning every old note, active-family non-exact warm starts run the full iteration budget with all notes movable. This deliberately favors correctness over a hierarchy-diff index; ordinary zero-force warm masks and exact cache hits remain unchanged. Cold, warm and explicit recompute requests borrow the same resolved hierarchy CSR. Preview remains finite and does not mutate worker baseline/cache state.

Regressions in `tests/family-pull.test.ts` independently reconstruct historical key bytes, reload a saved binary with the new field absent, compare exact positions, and check off/on parent-only invalidation and changed-force refusal. The dedicated independent cache review remains a merged-wave shipping requirement; deterministic tests and synthetic captures alone do not grant boundary acceptance.


## Settled-generation adoption (wave 12, supersedes hydration precedence above)

Producer `graph-ng-fa2@2` invalidates prior solver output, including legacy graphology migration. Binary format stays 3. Source/view, declared identity, complete live identity validation, checksums, quarantine and size boundaries remain intact. Hub gravity defaults to 2 on settings upgrade; explicit 0 remains off. Nonzero hub/family force values participate in canonical layout identity; zero optional forces are omitted.

Metadata completeness and physical settlement are separate conditions. Only complete, settled coordinates become a saved generation; encode refuses unsettled positions. Exact hits come only from saved settled generations, never an unfinished interim. The latest computed interim takes precedence over an older saved generation and receives full-budget unpinned continuation, including after large hydration churn. A provisional pass that only borrowed unchanged saved positions does not replace that saved generation with a competing interim.

Explicit recompute prepares coordinates without mutating worker authority. Only after settings and renderer coordinates commit does `adoptLayout` adopt the prepared result, regenerate identity for its options and replace the worker's saved/interim state. Failed settings or renderer preparation never adopts. A verified settled adoption uses the existing encode/cache path, even when the key is unchanged by another refinement; failed disk writes remain visible derived-cache errors, not a rollback of committed coordinates. Configure/project invalidate a pending adoption. View filtering remains a mask over the same force topology.


## Active overlap numerical identity (2026-11-16)

`layoutIdentity` includes `overlap: 2` only when `force.adjustSizes` is enabled. The marker participates in generation keys and layout hashes, so old overlap generations fail the existing hash check before exact reuse or warm seeding. Ordinary-mode identity and arithmetic remain unchanged. Producer stays `graph-ng-fa2@2` and binary format stays 3; the conditional numerical identity is the migration mechanism. Appearance remains excluded from layout identity, so the size-aware force uses a documented degree/count proxy rather than claiming exact rendered-radius collision avoidance.
## Message-friendly layout cancellation (2026-11-17)

The shared layout/refinement solver explicitly requests MessageChannel task yields rather than boosted `scheduler.yield()` continuations. Native Chromium testing showed that repeatedly boosted continuations could starve a queued Stop message until the iteration budget completed. Other callers retain the scheduler default. Each channel closes both ports on completion.

The solver yields at its configured batch/stream boundaries or after at least 50 ms of work since the last yield, then checks Stop immediately. A single solver iteration remains atomic and can exceed that target; this is not a hard real-time cancellation guarantee. The later [layout-engine decision](ADR-0010-layout-engine.md) supersedes the first-step requirement and adds interruptible force walks. No force equations, iteration order, position authority, cache identity, request ownership, deadline or unsettled-generation persistence rules change. Exact unstopped Float32 coordinates and bounded synthetic Stop latency are measured separately in [benchmarks](../benchmarks.md).

## Display-only ingestion and explicit Stop (2026-11-16)

Worker ingest identity depends on source identity, declared property keys and producer names, not projection display. Lines/Notes still changes declaration/projection/generation identity, but need not resend unchanged fact columns. Exclusion changes invalidate the adapter and force reset independently. In-flight notifications retain their dirty versions until acknowledgement, then a sliced audit compares the current facts with the acknowledged stamps. Identical hydration causes no extra refresh; real differences, including mid-batch reverts, remain dirty.

Stop intent belongs to the matching layout RPC, including while it waits behind another request. It is replayed after worker acknowledgement and targets only that RPC id at the current revision. It ends the solver at a cooperative boundary and returns the current finite coordinates through the ordinary response. Under [ADR-0010](ADR-0010-layout-engine.md), an immediate Stop can return validated starting coordinates without streaming or saving them as solved. Stopped results explicitly remain unsettled. Initial layout retains them as interim coordinates; recompute still requires the existing settings/renderer commit followed by acknowledged adoption. Keep refining starts from retained coordinates. No stop path permits encode of an unsettled generation or changes a deadline, revision, identity, or cache refusal boundary.

Ready-state property messages report unverified notes immediately without a waiting animation or time estimate. Current derived facts require the host's explicit verified flag; native cache availability does not silently verify a selected derived source. Resolver completion audits a maintained set of unverified paths in bounded slices. One audit runs at a time; native-refresh passes wait the configured debounce interval capped at one second before consuming coalesced events. Task yields alone are insufficient: a native resolver storm can repeatedly re-enter an otherwise single-flight scan and starve host indexing. Explicit verification bypasses or wakes that wait. Verified paths and worker updates already queued in either the debounce index or the adapter dirty map are skipped before rereading or rescheduling. The index owns native events before its flush exposes them to the adapter; auditing those queued paths would otherwise duplicate their row stamps and move their existing debounce slot. Native-only missing caches get a cheap availability probe instead of row construction and hashing; a discovered update reserves its existing dirty/version entry before the index notification. Unchanged stamps do not requeue ingestion. Verification-only notifications also include never-indexed paths through ordinary ingestion rather than promoting rows the worker never received. The audit is epoch-bound; invalidation or disposal wakes its timer and prevents stale work. Neither an event nor elapsed time alone establishes completeness.

The 2026-11-17 queued-path correction is measured on the matched 49k synthetic fixture: baseline **18,963.8 ms / 142,072 reads**, fixed **16,934.0 ms / 141,362 reads**, with two rebuilds and one index flush each. The unchanged-candidate control still costs 185,406 reads but finishes in 17,985.4 ms, so the historical five-second delay is load-sensitive rather than an established additive component cost. The regression proves zero duplicate audit reads/enqueues for already queued paths while retaining one-cycle verification. Exact ablations, commands and limits are recorded in the benchmark document; these numbers are not a general startup or production-readiness guarantee.


## Visual completion (2026-11-18)

A completed pass may now be physically settled **or** meet the worker's [visual stopping policy](ADR-0010-layout-engine.md#visual-stopping-policy). These outcomes are distinct in the worker reply. An optional `looksDone` bit in format-3 generation metadata preserves **Layout ready** and **Keep refining** on exact reopen or unchanged coordinate reuse. Metadata completeness, source checks, explicit adoption after a renderer/settings commit and the prohibition on saving an interrupted pass are unchanged.

Active visual stopping has a numerical revision in both the layout hash and the generation key. Full runs use the old identity, including its seed. Old manifests need no rewrite: an absent stopping field describes the historical full policy. A positive absolute convergence threshold or budgets too small for even the first visual decision also keep the old identity, since no pass with those options can produce a visual stop. An active visual-policy request cannot borrow, warm-seed or reopen a full-policy generation, or vice versa.
